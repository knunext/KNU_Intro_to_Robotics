상자에서 상자로

지금까지는 평면 위에서 RRT 가족을 봤어요. 이번엔 책상 위의 진짜 일입니다. 상자 A에 든 블록을 집어 칸막이 너머 상자 B에 넣으려면, 팔은 어떤 길로 움직여야 할까요?

같은 문제를 RRT, PRM, RRT*, BIT* 네 가지로 풀어 보고, 마지막에 홈 자세에서 출발해 집고, 옮기고, 놓고, 돌아오는 작업 전체를 이어 붙입니다. 오른쪽 그림은 페이지가 열릴 때 BIT*로 실제로 계획한 작업이에요.

문제 세우기

플래너가 아는 건 두 가지뿐입니다. 관절각이 이럴 때 팔이 어디 있는지(순기구학), 그리고 그 자세가 무언가에 부딪히는지(충돌 검사). 이 둘만 있으면 팔의 모양이 어떻든 ‘관절각 공간에서 점 하나 잇기’ 문제가 됩니다.

1

관절 셋, 눈에 보이는 C-space

이번 팔은 일부러 단순하게 만들었어요. 받침 회전 θ₁, 어깨 θ₂, 팔꿈치 θ₃ 세 관절이 독립이고, 손목은 집게가 늘 바닥을 보도록 나머지 둘에서 자동으로 계산합니다. 상자를 쌓는 팔레타이징 로봇이 바로 이런 구조예요. 위에서 집고 위에서 놓는 일에는 이걸로 충분합니다.

독립 관절이 셋이니 자세 하나가 3차원 공간의 점 하나가 됩니다. 2관절 팔은 평면, 7관절 팔은 7차원이라 그릴 수 없었죠. 3차원은 그릴 수 있는 가장 큰 C-space입니다. 오른쪽 상자가 그 공간이고, 점들은 팔이 무언가에 닿는 자세들의 경계예요. 색은 무엇에 닿는지를 뜻합니다.

핵심순기구학: 팔이 서 있는 수직 평면 안에서 손끝까지
\[\begin{aligned} r &= \class{an-1}{L_1\cos\theta_2} + \class{an-2}{L_2\cos(\theta_2+\theta_3)} \\ z &= H + L_1\sin\theta_2 + L_2\sin(\theta_2+\theta_3) \class{an-3}{{}- L_g} \end{aligned}\]
  1. 1위팔이 만드는 수평 거리. 어깨 각 θ₂만 들어갑니다.
  2. 2아래팔이 만드는 수평 거리. 아래팔의 기울기는 바닥 기준 θ₂+θ₃예요. 관절각은 앞 관절의 각에 누적됩니다.
  3. 3손목에서 집게 끝까지 아래로 내려온 길이. 집게가 늘 수직이라 상수예요.
그 평면을 받침이 θ₁만큼 돌린다
\[x = \class{an-1}{r}\cos\class{an-2}{\theta_1}, \qquad y = r\sin\theta_1\]
  1. 1식 (1)에서 구한 수평 거리. 받침이 돌아도 변하지 않아요.
  2. 2받침 회전은 팔이 서 있는 평면을 통째로 돌릴 뿐입니다. 그래서 θ₁과 (θ₂, θ₃)를 따로 풀 수 있어요.
손목은 자동: 집게가 늘 바닥을 보도록
\[\theta_4 = \class{an-1}{-\frac{\pi}{2}} \class{an-2}{{}- (\theta_2 + \theta_3)}\]
  1. 1바닥을 향한 방향 (−90°)
  2. 2아래팔이 기운 만큼 손목을 반대로 꺾어 상쇄합니다.
역기구학: 손끝 위치 → 관절각 (팔꿈치가 위로 가는 해)
\[\begin{aligned} \theta_1 &= \class{an-1}{\mathop{\mathrm{atan2}}(y,\,x)} \\ \cos\theta_3 &= \class{an-2}{\frac{d^2 - L_1^2 - L_2^2}{2L_1L_2}}, \qquad \class{an-3}{\theta_3 \lt 0} \\ \theta_2 &= \mathop{\mathrm{atan2}}(w_z,\, w_r) - \class{an-4}{\mathop{\mathrm{atan2}}(L_2\sin\theta_3,\; L_1 + L_2\cos\theta_3)} \end{aligned}\]
  1. 1위에서 내려다본 방향각. atan2는 사분면까지 맞춰 주는 arctan이에요.
  2. 2코사인 법칙. 세 변이 L₁, L₂, d인 삼각형에서 팔꿈치 각을 구합니다.
  3. 3해가 두 개(팔꿈치 위·아래)라서 하나를 골라야 해요. 음수 쪽이 팔꿈치 위입니다.
  4. 4어깨→손목 직선과 위팔 사이의 각. 이만큼 위팔을 더 들어 올립니다.
주의역기구학의 해는 하나가 아닐 수 있어요. 이 팔은 두 개, 7관절 팔은 무한히 많습니다. 플래너에 목표 자세를 넘길 때 어떤 해를 골랐는지에 따라 경로가 달라집니다.

\((w_r, w_z)\)는 어깨에서 본 손목 위치, \(d = \sqrt{w_r^2 + w_z^2}\)는 어깨에서 손목까지의 거리입니다. 이 팔의 치수는 \(H = 0.14\), \(L_1 = 0.30\), \(L_2 = 0.26\), \(L_g = 0.11\) (m).

파이썬
import numpy as np
H, L1, L2, LG = 0.14, 0.30, 0.26, 0.11

def fk(q):                                   # 관절각 3개 -> 점 네 개
    t1, t2, t3 = q
    re, ze = L1*np.cos(t2), H + L1*np.sin(t2)
    rw, zw = re + L2*np.cos(t2+t3), ze + L2*np.sin(t2+t3)
    u = np.array([np.cos(t1), np.sin(t1), 0.0])  # 받침이 보는 방향
    S = np.array([0, 0, H])                  # 어깨
    E = re*u + [0, 0, ze]                    # 팔꿈치
    W = rw*u + [0, 0, zw]                    # 손목
    T = W - [0, 0, LG]                       # 손끝(집게 가운데)
    return S, E, W, T

def capsule_hits_box(a, b, r, bmin, bmax, n=24):
    for t in np.linspace(0, 1, n):           # 선분 위 점마다
        p = a + (b - a)*t
        d = np.maximum(0, np.maximum(bmin - p, p - bmax))
        if d @ d < r*r:                       # 상자까지 거리 < 반지름
            return True
    return False

핵심

작업 공간의 칸막이 하나가 C-space에서는 휘어진 덩어리가 됩니다. 이 모양을 미리 다 계산하는 건 차원이 높아지면 불가능하니, 플래너는 지도를 그리지 않고 자세 하나씩 물어보면서 길을 찾아요. 오른쪽 점구름은 공부용으로 미리 뿌려 본 것일 뿐입니다.

2

RRT: 다시 한 번, 이번엔 3D로

RRT는 이미 해 봤죠. 무작위 점을 뽑고, 트리에서 가장 가까운 노드를 찾아, 그쪽으로 한 걸음(η) 뻗습니다. 달라진 건 점이 3차원이라는 것, 그리고 한 걸음을 검사하는 비용이에요. 노드와 노드 사이를 0.03 rad 간격으로 잘라 자세마다 충돌 검사를 하므로, 0.3 rad 한 걸음이 검사 10번입니다. 실제 플래너의 시간 대부분이 여기서 나가요.

RRT는 길을 빨리 찾지만 길이에는 관심이 없습니다. 그래서 찾은 뒤에 다듬기(shortcut)를 거의 항상 붙여요. 경로 위 두 점을 무작위로 골라, 그 사이가 곧장 이어지면 중간을 버리는 걸 여러 번 반복합니다.

핵심한 걸음 뻗기 (steer)
\[q_{\mathrm{new}} = q_{\mathrm{near}} + \class{an-1}{\eta}\,\class{an-2}{\frac{q_{\mathrm{rand}} - q_{\mathrm{near}}}{\lVert q_{\mathrm{rand}} - q_{\mathrm{near}} \rVert}}\]
  1. 1한 걸음의 길이 (rad). 크면 빨리 퍼지지만 좁은 틈을 건너뛰어 버려요.
  2. 2qrand 쪽을 가리키는 길이 1짜리 방향 벡터
구간 검사: 간격 Δ로 잘라 자세마다 묻기
\[n = \class{an-1}{\left\lceil \frac{\lVert q_b - q_a \rVert}{\Delta} \right\rceil}, \qquad \class{an-2}{\mathrm{free}\!\left(q_a + \tfrac{k}{n}\,(q_b - q_a)\right)}, \quad k = 1, \dots, n\]
  1. 1구간을 몇 조각으로 자를지. 구간이 길수록 검사가 늘어요.
  2. 2k번째 중간 자세. 이것 하나마다 충돌 검사 한 번입니다.
목표 쪽으로 끌기 (goal bias)
\[q_{\mathrm{rand}} = \begin{cases} q_{\mathrm{goal}} & \text{with prob. } \class{an-1}{0.1} \\ \mathrm{Uniform}(\mathcal{C}) & \text{otherwise} \end{cases}\]
  1. 110%만 목표를 그대로 뽑습니다. 너무 크면 장애물 앞에서 같은 시도만 되풀이해요.

이 실습: \(\eta = 0.3\) rad, \(\Delta = 0.03\) rad. 그래서 한 걸음이 충돌 검사 10번입니다.

파이썬
def rrt(qs, qg, eta=0.3, bias=0.1, iters=5000):
    nodes, parent = [qs], [-1]
    for _ in range(iters):
        q_rand = qg if rng.random() < bias else sample()
        i = np.argmin([np.linalg.norm(q - q_rand) for q in nodes])
        q_new = steer(nodes[i], q_rand, eta)
        if not edge_free(nodes[i], q_new):
            continue
        nodes.append(q_new); parent.append(i)
        if np.linalg.norm(q_new - qg) < eta and edge_free(q_new, qg):
            nodes.append(qg); parent.append(len(nodes) - 2)
            return trace(nodes, parent)

def edge_free(qa, qb, res=0.03):           # 잘게 잘라 자세마다 검사
    n = max(1, int(np.ceil(np.linalg.norm(qb - qa) / res)))
    return all(free(qa + (qb - qa)*k/n) for k in range(1, n + 1))

def shortcut(path, iters=100):             # 다듬기
    for _ in range(iters):
        i, j = sorted(rng.choice(len(path), 2, replace=False))
        if j - i > 1 and edge_free(path[i], path[j]):
            path = path[:i+1] + path[j:]
    return path

핵심

3

PRM: 지도를 먼저 만들고, 길은 나중에

RRT는 질문 하나마다 트리를 새로 키웁니다. 그런데 집 안 로봇은 같은 책상 앞에서 수십 번 움직이죠. PRM(확률적 로드맵)은 일을 두 단계로 나눕니다. 먼저 충돌 없는 자세를 잔뜩 뿌리고 가까운 것끼리 이어 지도(그래프)를 만들어 둡니다. 그 뒤 질문이 오면 시작과 목표만 지도에 붙이고 A*로 길을 찾아요. 그래프 탐색은 이미 아는 그대로입니다.

지도 만들기는 비쌉니다. 이 실습에서는 노드 250개, 이웃 10개씩이라 충돌 검사가 2만 번을 넘어요. 대신 그다음 질문들은 수백 번이면 끝납니다. 환경이 그대로이고 질문이 많을수록 PRM이 이득이에요.

지도 = 그래프 G = (V, E)
\[\begin{aligned} V &= \{\, q_i \sim \mathrm{Uniform}(\mathcal{C}) \;:\; \class{an-1}{\mathrm{free}(q_i)} \,\}, \qquad |V| = N \\ E &= \{\, (i,j) \;:\; \class{an-2}{j \in \mathrm{kNN}(i)},\ \ \class{an-3}{q_i \to q_j \text{ is free}} \,\} \\ w(i,j) &= \lVert q_i - q_j \rVert \end{aligned}\]
  1. 1노드는 충돌 없는 자세만. 자세 하나 = 검사 한 번이라 싸요.
  2. 2가까운 이웃 k개만 간선 후보로 봅니다.
  3. 3간선마다 구간 검사. 지도 만들기 비용의 대부분이 여기서 나가요.
핵심질의: 시작·목표를 지도에 붙인 뒤 A*
\[f(v) = \class{an-1}{g(v)} + \class{an-2}{h(v)}, \qquad h(v) = \lVert q_v - q_{\mathrm{goal}} \rVert \;\class{an-3}{\le\; h^{\ast}(v)}\]
  1. 1시작에서 v까지 지도 위로 실제로 온 비용
  2. 2v에서 목표까지 남은 비용의 추정 (직선거리)
  3. 3추정이 실제 남은 비용 h*보다 크지 않아요(허용 가능). 그래서 A*가 최단 경로를 보장합니다.

이 실습: \(N = 250\), \(k = 10\).

파이썬 (networkx)
import networkx as nx

def build_prm(N=250, k=10):              # 한 번만
    G = nx.Graph()
    while G.number_of_nodes() < N:
        q = sample()
        if free(q):
            G.add_node(len(G), q=q)
    Q = np.array([G.nodes[i]['q'] for i in G])
    for i in G:
        d = np.linalg.norm(Q - Q[i], axis=1)
        for j in np.argsort(d)[1:k+1]:
            if not G.has_edge(i, j) and edge_free(Q[i], Q[j]):
                G.add_edge(i, int(j), w=d[j])
    return G

def query(G, qs, qg, k=10):              # 질문마다
    ids = [i for i in G if isinstance(i, int)]
    Q = np.array([G.nodes[i]['q'] for i in ids])
    for name, q in (('s', qs), ('g', qg)):
        G.add_node(name, q=q)
        d = np.linalg.norm(Q - q, axis=1)
        for j in np.argsort(d)[:k]:
            if edge_free(q, Q[j]):
                G.add_edge(name, ids[j], w=d[j])
    h = lambda a, b: np.linalg.norm(G.nodes[a]['q'] - G.nodes[b]['q'])
    return nx.astar_path(G, 's', 'g', heuristic=h, weight='w')

  • 지도가 완성되면 질문을 바꿔 보세요. [B 위 → 홈], [홈 → A 위]는 지도를 다시 만들지 않으니 충돌 검사가 수백 번만 늘어요.
  • A*가 지도를 훑는 순서를 보세요. 목표 쪽 노드부터 펼치니 지도의 일부만 보고 끝납니다.

핵심

PRM은 비싼 일(충돌 검사)을 앞으로 몰아 두고, 질문은 싼 그래프 탐색으로 처리합니다. 대신 환경이 바뀌면 지도의 간선을 다시 확인해야 해요. 7장에서 블록을 들었을 때 이 문제를 ‘필요한 간선만 다시 검사’하는 방법으로 풉니다.

4

RRT*: 고르고, 고친다

평면에서 본 RRT*를 3D에 그대로 옮겼습니다. 새 노드를 붙일 때 가장 가까운 노드가 아니라 반지름 r 안에서 출발점부터의 비용이 가장 싼 노드를 부모로 고르고(choose parent), 붙인 뒤에는 이웃들 중 새 노드를 거치면 더 싸지는 것들의 부모를 바꿉니다(rewire). 그래서 시간을 더 줄수록 경로가 짧아져요.

값은 충돌 검사로 치릅니다. 이웃마다 구간 검사가 붙으니, 같은 반복 횟수에서 RRT보다 검사가 훨씬 많아요. 아래 그래프가 충돌 검사를 쓸수록 경로 길이가 어떻게 줄어드는지 보여 줍니다.

이웃 반지름 (차원 d = 3, 노드 수 n)
\[r(n) = \min\!\left( \class{an-1}{1.5\,\eta},\;\; \class{an-2}{\gamma \left( \frac{\log n}{n} \right)^{1/d}} \right)\]
  1. 1처음에는 이 상한이 걸립니다.
  2. 2노드가 늘수록 줄어들어 이웃 수를 대략 log n개로 유지해요. 계산은 억제하면서 최적성은 지킵니다.
핵심부모 고르기
\[\mathrm{parent}(q_{\mathrm{new}}) = \operatorname*{arg\,min}_{i \,\in\, \mathcal{N}(q_{\mathrm{new}}),\ \class{an-2}{i \to q_{\mathrm{new}} \text{ free}}} \; \class{an-1}{c(i) + \lVert q_i - q_{\mathrm{new}} \rVert}\]
  1. 1i를 거쳐 qnew까지 오는 총비용. RRT는 ‘가장 가까운’ 노드를 골랐지만 RRT*는 ‘출발점부터 가장 싼’ 노드를 고릅니다.
  2. 2실제로 이어지는 이웃 중에서만
다시 잇기 (이웃 j마다)
\[\class{an-1}{c(\mathrm{new}) + \lVert q_{\mathrm{new}} - q_j \rVert} \lt \class{an-2}{c(j)} \;\;\Longrightarrow\;\; \mathrm{parent}(j) \leftarrow \mathrm{new}\]
  1. 1새 노드를 거쳐 j로 가는 비용
  2. 2j의 지금 비용. 이게 더 비싸면 부모를 새 노드로 바꿉니다.

\(c(i)\)는 출발점에서 노드 \(i\)까지 트리를 따라간 비용, \(\mathcal{N}\)은 반지름 \(r\) 안의 이웃입니다. 부모가 바뀌면 \(j\)의 자손들 비용도 같은 만큼 줄어요. 이 실습: \(\eta = 0.4\), \(\gamma = 2.6\), 반복 1500번.

파이썬 (RRT에서 바뀌는 부분)
# q_new를 만들고 자세 자체가 충돌 없음을 확인한 뒤
n = len(nodes) + 1
r = min(1.5*eta, gamma * (np.log(n) / n) ** (1/3))
near = [i for i in range(len(nodes)) if dist(nodes[i], q_new) <= r]

# 1) 부모 고르기: 싼 순서로 보면서 처음 이어지는 것
near.sort(key=lambda i: cost[i] + dist(nodes[i], q_new))
p = next((i for i in near if edge_free(nodes[i], q_new)), None)
if p is None:
    continue
new = add_node(q_new, parent=p, cost=cost[p] + dist(nodes[p], q_new))

# 2) 다시 잇기
for j in near:
    c = cost[new] + dist(q_new, nodes[j])
    if c < cost[j] and edge_free(q_new, nodes[j]):
        set_parent(j, new)        # 자손들의 cost도 같은 만큼 줄어든다

해 볼 것

  • 트리 모양을 RRT와 비교해 보세요. RRT*의 가지는 출발점에서 부채꼴로 곧게 뻗습니다. 다시 잇기가 구불구불한 가지를 계속 펴기 때문이에요.
  • 첫 경로가 나온 직후와 1500번째 반복의 경로 길이를 비교해 보세요. 그래프의 계단이 언제 촘촘하고 언제 뜸해지는지도요.
  • C-space의 투명한 공이 이웃 반지름 r입니다. 노드가 늘수록 작아지는 게 보이나요?

핵심

RRT*는 ‘언제 멈춰도 그때까지의 최선을 주는’ anytime 플래너이고, 무한히 돌리면 최단 경로에 수렴합니다. 다만 경로를 줄이는 데 도움이 안 되는 곳까지 고르게 검사하느라 충돌 검사를 많이 써요. 다음 장의 BIT*가 바로 이 낭비를 겨냥합니다.

5

BIT*: 표본은 한꺼번에, 검사는 마지막에

BIT*(Batch Informed Trees)는 지금까지 본 아이디어 네 가지를 합칩니다. PRM처럼 표본을 한 묶음(batch)씩 미리 뿌리고, A*처럼 우선순위 큐로 ‘가장 유망한 간선’부터 보며, Informed RRT*처럼 경로를 찾은 뒤에는 그보다 짧아질 수 있는 타원 안에만 새 표본을 뿌립니다. 그리고 가장 중요한 하나, 간선을 큐에 넣을 때는 검사하지 않고 꺼내서 실제로 쓸 차례가 됐을 때만 충돌 검사를 합니다(지연 검사, lazy).

큐의 순서를 정하는 값은 ‘이 간선을 지나는 경로가 아무리 잘 돼도 이 정도는 든다’는 추정치예요. 이 값이 지금 최선의 경로보다 크면 검사할 필요조차 없습니다. 충돌 검사가 비쌀수록 이 차이가 커져요.

추정치: 직선거리라 실제 비용보다 크지 않다
\[\class{an-1}{\hat g(x)} = \lVert x - q_{\mathrm{start}} \rVert, \qquad \class{an-2}{\hat h(x)} = \lVert x - q_{\mathrm{goal}} \rVert, \qquad \class{an-3}{\hat c(v,x)} = \lVert v - x \rVert\]
  1. 1시작에서 x까지. 어떤 경로도 이보다 짧을 수 없어요.
  2. 2x에서 목표까지
  3. 3간선의 길이. 충돌 검사 전이라 ‘막혀 있지 않다면’의 값입니다.
핵심두 우선순위 큐의 키 (작을수록 먼저 꺼낸다)
\[\mathrm{key}_V(v) = g(v) + \hat h(v), \qquad \mathrm{key}_E(v,x) = \class{an-1}{g(v)} + \class{an-2}{\hat c(v,x)} + \class{an-3}{\hat h(x)}\]
  1. 1트리를 따라 v까지 실제로 온 비용 (이미 검사함)
  2. 2v→x 간선 길이 (아직 검사 안 함)
  3. 3x에서 목표까지 남은 추정
알아 두기keyE는 ‘v→x를 지나는 경로는 아무리 잘 돼도 이만큼은 든다’는 하한이에요. A*의 f = g + h와 같은 모양입니다.
쓸모 있을 수 있는 표본 = 타원 안
\[\class{an-1}{\hat g(x) + \hat h(x) \lt c_{\mathrm{best}}}, \qquad r_1 = \class{an-2}{\frac{c_{\mathrm{best}}}{2}}, \quad r_2 = r_3 = \class{an-3}{\frac{\sqrt{c_{\mathrm{best}}^2 - c_{\min}^2}}{2}}\]
  1. 1시작과 목표를 두 초점으로 하는 타원(3차원에서는 회전타원체)의 안쪽
  2. 2긴 반지름. 경로가 짧아질수록 줄어요.
  3. 3짧은 반지름. cbest가 cmin에 가까워지면 0으로 가서 타원이 홀쭉해집니다.
멈춤 규칙: 이 묶음에서 더 볼 것이 없다
\[\class{an-1}{\min_{(v,x) \,\in\, Q_E} \mathrm{key}_E(v,x)} \;\ge\; c_{\mathrm{best}} \;\;\Longrightarrow\;\; \text{next batch}\]
  1. 1가장 유망한 간선조차 지금 최선을 못 이기면, 나머지는 검사할 필요가 없어요.

\(g(v)\)는 트리를 따라간 실제 비용, \(c_{\mathrm{best}}\)는 지금까지 찾은 최선 경로의 길이입니다. \(c_{\min} = \lVert q_{\mathrm{goal}} - q_{\mathrm{start}} \rVert\). 이 실습: 묶음당 표본 \(m = 60\).

파이썬 (뼈대)
def bit_star(m=60, batches=10):
    V, X = {start}, {goal}                 # 트리, 아직 안 붙은 표본
    g = {start: 0.0}; parent = {}; c_best = inf
    for _ in range(batches):
        X |= sample_batch(m, c_best)       # 경로가 있으면 타원 안에만
        X = {x for x in X if g_hat(x) + h_hat(x) < c_best}
        r = radius(len(V) + len(X))
        QV, QE = list(V), []
        while True:
            # 1) 정점이 간선보다 유망하면 펼쳐서 간선 후보를 큐에
            while QV and min_key(QV, vkey) <= min_key(QE, ekey):
                v = pop_min(QV, vkey)
                for x in near(X | V, v, r):
                    if g_hat(v) + d(v, x) + h_hat(x) < c_best:
                        QE.append((v, x))
            if not QE:
                break
            # 2) 가장 유망한 간선 하나
            v, x = pop_min(QE, ekey)
            if ekey((v, x)) >= c_best:
                break                      # 남은 건 모두 쓸모없다
            if g[v] + d(v, x) < g.get(x, inf) and edge_free(v, x):
                if x not in V:             # 검사는 여기서 처음 한다
                    V.add(x); X.discard(x); QV.append(x)
                parent[x] = v; g[x] = g[v] + d(v, x)
                if x == goal:
                    c_best = g[goal]
    return trace(parent, goal)

해 볼 것

  • 첫 묶음을 보세요. 회색 표본 60개가 한꺼번에 뿌려지고, 트리는 목표 쪽으로 곧장 자랍니다. RRT처럼 사방으로 퍼지지 않아요. 큐가 ‘목표에 가까워 보이는’ 간선부터 꺼내기 때문입니다.
  • 경로를 찾으면 C-space에 타원이 나타납니다. 다음 묶음부터 표본이 그 안에만 생기고, 경로가 짧아질수록 타원도 홀쭉해져요.
  • 그래프에서 RRT*(점선)와 비교해 보세요. 같은 충돌 검사 수에서 BIT*의 경로가 더 짧습니다.

핵심

BIT*의 힘은 검사할 간선을 고르는 순서에서 나옵니다. 정렬은 싸고 충돌 검사는 비싸니, 싼 계산으로 비싼 계산을 아끼는 거예요. 자료구조 수업의 우선순위 큐가 로봇 플래너의 핵심 부품이 되는 장면입니다.

6

넷을 같은 문제에

같은 문제를 씨앗(난수)만 바꿔 다섯 번씩 풀어 평균을 냈습니다. 눈여겨볼 열은 둘이에요. 첫 경로까지 충돌 검사는 ‘얼마나 빨리 길을 찾나’, 경로 길이는 ‘얼마나 좋은 길인가’입니다. 다듬기는 경로를 찾은 뒤 따로 120번 시도했어요.

해 볼 것

  • 표 아래 칩을 눌러 경로를 하나씩 켜고 꺼 보세요. 왼쪽에서는 손끝이 지나는 길로, 오른쪽에서는 C-space의 곡선으로 보입니다.
  • RRT에 다듬기를 붙인 길이와 BIT*의 길이를 비교해 보세요. 다듬기는 싸고 효과가 크지만, 처음 찾은 길의 ‘방향’까지 바꾸지는 못해요.

핵심

빨리 아무 길이나: RRT 계열. 같은 곳에서 여러 번: PRM. 시간을 들여 좋은 길: RRT*보다 BIT* 같은 최신 방법. 정답 하나가 아니라 무엇이 비싼가(검사, 시간, 질문 수)에 따라 고릅니다.

3부

작업으로 이어 붙이기

경로 계획은 작업의 일부일 뿐입니다. 블록을 옮기려면 다가가고, 똑바로 내려가고, 집고, 들고, 옮기고, 놓고, 돌아와야 해요. 계획이 필요한 구간과 아닌 구간을 나누는 게 첫 번째 설계입니다.

7

집어서 옮기기

작업은 아홉 단계예요. 넓은 공간을 가로지르는 세 구간만 플래너가 맡고, 상자 안으로 넣고 빼는 구간은 손끝을 수직 직선으로 움직이며 매 순간 역기구학을 풉니다. 상자 벽 사이 좁은 곳을 무작위 표본으로 통과하는 건 비효율적이고, 집기 직전에는 손의 궤적 자체가 정해져 있어야 하니까요. 실제 시스템에서도 같은 분업을 합니다.

블록을 집는 순간 팔의 몸이 바뀝니다. 그래서 가운데 구간은 블록까지 포함해 충돌 검사를 해요. PRM은 블록 없이 만든 지도를 재사용하되, A*가 찾은 경로의 간선만 블록을 든 몸으로 다시 검사합니다. 걸리는 간선이 있으면 그것만 지우고 다시 찾아요(Lazy PRM).

해 볼 것

  • 플래너를 바꿔 가며 실행하고 아래 표의 충돌 검사 수를 비교해 보세요. PRM은 첫 구간에서 지도를 만드느라 비싸고, 나머지 두 구간은 아주 쌉니다.
  • 블록을 집는 순간 오른쪽 C-space의 점구름이 두꺼워지는 걸 보세요. 놓으면 다시 얇아집니다.
  • [다듬기]를 끄고 RRT로 실행해 보세요. 팔이 쓸데없이 크게 돌아가는 동작이 실제 로봇에서 왜 문제일지 생각해 보세요. 시간도 들고, 사람이 예측하기도 어렵습니다.

핵심

‘경로 계획’은 작업 계획의 한 단계입니다. 어떤 구간을 플래너에 맡기고 어떤 구간을 직선과 IK로 처리할지, 무엇을 들었는지에 따라 충돌 모델을 어떻게 바꿀지가 실제 시스템 설계의 대부분이에요. 가사 로봇 프로젝트의 ‘집기’ 스킬도 이 구조 그대로 만들 수 있습니다.

정리

  1. C-space: 관절각 묶음 하나가 점 하나. 작업 공간의 장애물은 C-space에서 휘어진 덩어리가 되고, 무엇을 들었는지에 따라 모양이 바뀝니다.
  2. 충돌 검사가 비용: 플래너 시간의 대부분은 구간을 잘게 잘라 자세마다 검사하는 데 씁니다. 그래서 알고리즘을 비교할 때 반복 횟수보다 충돌 검사 수를 봅니다.
  3. RRT는 빠르게 하나, PRM은 지도를 만들어 여러 번, RRT*는 시간을 들여 점점 짧게, BIT*는 우선순위 큐와 지연 검사로 같은 검사 수에 더 좋은 길.
  4. 작업 = 계획 구간 + 직선 구간 + 집기/놓기. 넓은 공간은 플래너, 좁은 접근은 직선 경로와 IK로 나눕니다.
RRT, RRT-Connect질문이 한 번이고 빨리 답해야 할 때. 찾은 뒤 다듬기를 붙인다. MoveIt의 기본 플래너가 RRT-Connect다.
PRM, Lazy PRM같은 작업대 앞에서 여러 번 움직일 때. 환경이 조금 바뀌면 경로 위 간선만 다시 검사한다.
RRT*시간 여유가 있고 짧은 경로가 중요할 때. 개념이 단순해서 최적성의 원리를 배우기 좋다.
BIT*충돌 검사가 비싸고 좋은 경로가 필요할 때. OMPL에 BITstar로 들어 있고, AIT*·EIT* 같은 후속 연구로 이어진다.

이 네 가지는 모두 오픈소스 모션 플래닝 라이브러리 OMPL에 들어 있어서(RRT, PRM, LazyPRM, RRTstar, BITstar), MuJoCo 시뮬레이터에 붙일 때는 ‘자세가 충돌인가’ 함수 하나만 넘겨주면 됩니다. 그 함수가 1장에서 본 mj_forward와 접촉 수 확인이에요.
