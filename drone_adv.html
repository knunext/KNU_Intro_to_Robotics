자세를 행렬로 잡고, 게이트를 지난다

2D에서는 기울기가 θ 하나였습니다. 3D 드론의 자세는 3×3 회전 행렬이에요. 행렬의 세 열이 곧 기체의 앞, 옆, 위 방향이라서, 추력이 어디를 향하는지는 셋째 열 하나로 끝납니다.

이 페이지는 두 부분입니다. 1부에서 회전 행렬, 오일러 각과 짐벌 락, 쿼터니언, 그리고 회전을 그대로 다루는 기하 제어로 공중제비까지 해 봅니다. 2부에서는 사각형 게이트 여섯 개를 지나는 자율 드론 레이싱을 맛보고, 실제 대회에 나가려면 무엇이 더 필요한지 정리해요.

b₁ 앞 b₂ 옆(왼쪽) b₃ 위, 추력 방향 목표와 다음 게이트
1단계부터 시작

4장의 최소 스냅 궤적과 기하 제어로 24 m × 14 m 경기장을 도는 레이싱 기체(추력/무게 4). 궤적 색은 속도이고, 기체는 실제보다 크게 그렸어요.

1부

자세: 회전을 회전 그대로 다룬다

PID 실습 7장의 3D 드론은 롤·피치·요 세 각도로 자세를 다뤘습니다. 작은 기울기에선 충분하지만, 크게 기울거나 뒤집히면 세 각도가 엉뚱하게 뛰어요. 여기서는 자세를 행렬과 쿼터니언으로 다루는 법을 배우고, 그 위에서 도는 제어기를 만듭니다.

1

세 개의 열이 곧 기체의 세 축

기체에 붙은 좌표축 세 개를 생각해 봅시다. 앞 b₁, 왼쪽 b₂, 위 b₃. 이 세 방향을 세계 좌표로 적어 나란히 세우면 3×3 행렬 R이 되고, 이게 자세의 전부예요. 행렬을 열 단위로 읽는 게 핵심입니다. 첫째 열은 “기수가 세계에서 어디를 보나”, 셋째 열은 “추력이 세계에서 어디를 향하나”예요.

R은 아무 행렬이나 될 수 없습니다. 세 축은 길이가 1이고 서로 수직이며, 오른손 법칙을 따라요. 이 조건이 R⊤R = I, det R = 1이고, 이런 행렬의 모임을 SO(3)라고 부릅니다. 덕분에 역행렬은 그냥 전치예요. 기체 좌표의 벡터를 세계로 바꿀 땐 R을 곱하고, 반대로는 R⊤를 곱합니다.

자세는 각속도로 변합니다. 기체가 ω로 돌면 0.001초 뒤의 자세는 지금 자세에 “그 축으로 |ω|·Δt만큼 도는 작은 회전”을 곱한 것이에요. 2D 페이지에서 θ에 θ̇·Δt를 더하던 것이 3D에선 곱하기가 됩니다. 회전은 더하면 안 되고 이어 붙여야 하니까요.

자세 = 세 축을 세운 행렬
(1)
  1. 1기수 방향(앞). 1인칭 카메라가 보는 쪽이에요.
  2. 2왼쪽 방향. 피치 회전은 이 축을 중심으로 돕니다.
  3. 3위쪽 = 추력 방향. W는 세계(world), B는 기체(body) 좌표예요.
3D 운동 방정식
(2)
  1. 1추력 f가 셋째 열 방향으로. 2D 식 (1)의 F sin θ, F cos θ가 이 한 줄에 들어 있어요. 모터 네 개의 합이 f입니다.
  2. 2자세의 변화. ω̂는 각속도로 만든 반대칭 행렬이에요(아래 식).
  3. 3토크. 모터 네 개의 추력 차이로 롤·피치 토크가, 프로펠러 회전 방향 차이로 요 토크가 생깁니다. 마지막 항은 돌고 있는 물체의 자이로 효과예요.
각속도로 자세 갱신하기
(3)
  1. 1한 칸씩 곱해 나갑니다. exp(ω̂Δt)는 ω 축으로 |ω|Δt만큼 도는 회전 행렬이고, 로드리게스 공식으로 바로 계산돼요. 오차가 쌓여 열들이 조금씩 비뚤어지면 가끔 다시 직교화합니다.
핵심행렬은 열로 읽으세요. R의 셋째 열이 추력 방향이고, 위치 제어기가 원하는 가속도 방향으로 이 열을 돌려놓는 것이 드론 제어의 전부입니다.
파이썬
import numpy as np
def Rx(a): c, s = np.cos(a), np.sin(a); return np.array([[1, 0, 0], [0, c, -s], [0, s, c]])
def Ry(a): c, s = np.cos(a), np.sin(a); return np.array([[c, 0, s], [0, 1, 0], [-s, 0, c]])
def Rz(a): c, s = np.cos(a), np.sin(a); return np.array([[c, -s, 0], [s, c, 0], [0, 0, 1]])

R = Rz(np.radians(45)) @ Ry(np.radians(-10)) @ Rx(np.radians(20))
b1, b2, b3 = R[:, 0], R[:, 1], R[:, 2]        # 열 = 기체의 앞, 옆, 위
thrust_W = R @ np.array([0, 0, 0.3])          # 추력은 셋째 열 방향
assert np.allclose(R.T @ R, np.eye(3))        # 열끼리 수직, 길이 1
assert np.isclose(np.linalg.det(R), 1.0)      # 오른손 좌표

def hat(w):                                   # ω̂ x = ω × x
    return np.array([[0, -w[2], w[1]], [w[2], 0, -w[0]], [-w[1], w[0], 0]])

def step_R(R, w, dt):                         # 자세는 더하지 않고 곱한다
    a = np.linalg.norm(w) * dt
    if a < 1e-12:
        return R
    K = hat(w / np.linalg.norm(w))
    return R @ (np.eye(3) + np.sin(a) * K + (1 - np.cos(a)) * K @ K)

해 볼 것

  • 롤 슬라이더만 움직여 보세요. 첫째 열(빨강)은 그대로이고 둘째, 셋째 열만 바뀝니다. 롤은 기수 축(b₁)을 중심으로 도는 회전이니까요.
  • 요를 90°로 두면 첫째 열이 (0, 1, 0)이 됩니다. 기수가 세계의 y축을 봐요. 셋째 열은 (0, 0, 1) 그대로라서 추력 방향은 바뀌지 않습니다.
  • [뒤집기]를 누르면 셋째 열의 z 성분이 −1이 됩니다. 추력이 땅을 향해요. 오른쪽 아래 검사 칸은 어떤 자세에서도 열 길이 1, 내적 0, det 1을 유지합니다.
  • 행렬의 열 이름을 누르면 3D 화면에서 그 축이 굵게 강조돼요. 화면을 끌어서 카메라를 돌려 볼 수 있습니다.

핵심

자세는 세 축을 열로 세운 회전 행렬 R입니다. 열을 읽으면 기수와 추력이 세계에서 어디를 향하는지 바로 보이고, 자세의 변화는 작은 회전을 곱해 나가는 것으로 계산해요.

2

숫자 세 개의 함정과 네 개의 해법

사람에게 편한 건 롤·피치·요 세 각도, 오일러 각입니다. 요로 돌고, 그다음 피치, 마지막에 롤을 차례로 돌린 결과가 자세예요. 그런데 피치가 정확히 90°가 되면 롤 축이 처음의 요 축과 같은 방향을 가리키게 됩니다. 두 슬라이더가 같은 회전을 만들고, 한 방향의 회전은 아예 만들 수 없어요. 이걸 짐벌 락이라고 부릅니다. 아폴로 우주선의 관성 항법 장치가 피해 다녀야 했던 바로 그 현상이에요.

문제는 오일러 각만의 것이 아닙니다. 3차원 회전을 숫자 세 개로 적는 방법은 어느 것이든 어딘가에서 이런 특이점을 가져요. 그래서 계산할 때는 숫자 네 개짜리 쿼터니언을 씁니다. 회전축 u와 회전각 α를 cos(α/2), u·sin(α/2)로 담은 길이 1인 벡터예요. 특이점이 없고, 행렬보다 가볍고, 두 자세 사이를 가장 짧은 회전으로 잇는 보간(slerp)이 깔끔합니다.

대신 쿼터니언은 사람이 읽기 어렵습니다. 그래서 실제 비행 소프트웨어는 화면과 설정에는 오일러 각을, 계산에는 쿼터니언이나 회전 행렬을 써요. 하나 기억할 것은 q와 −q가 같은 자세라는 점입니다. 보간할 때 둘 중 가까운 쪽을 골라야 먼 길로 돌지 않아요.

오일러 각 (Z-Y-X 순서)
(4)
  1. 1요 ψ. 세계의 z축으로 먼저 돌립니다. 바깥 고리예요.
  2. 2피치 θ. 돌아간 y축으로. 이 좌표계에서는 θ > 0이면 기수가 내려갑니다(오른손 법칙).
  3. 3롤 φ. 마지막으로 기체의 x축으로. 안쪽 고리예요.
짐벌 락: 두 각이 합쳐진다
(5)
  1. 1φ와 ψ가 따로 의미를 잃고 차이만 남습니다. (φ, ψ) = (40°, 10°)와 (60°, 30°)는 같은 자세예요. 반대로, 이 자세에서 기체 z축으로 살짝 도는 회전은 어떤 슬라이더로도 만들 수 없습니다.
쿼터니언과 slerp
(6)
  1. 1회전축과 회전각. 어떤 자세든 축 하나로 한 번 돌린 것으로 쓸 수 있어요(오일러의 회전 정리).
  2. 2구 위의 직선 보간. Ω는 두 쿼터니언 사이의 각이에요. s를 0에서 1로 바꾸면 같은 축으로 일정한 속도로 돕니다.
주의오일러 각으로 보간하면(각 숫자를 따로 선형 보간) 같은 두 자세 사이를 훨씬 먼 길로 돌기도 합니다. 실습의 [보간 비교]에서 기수 끝이 그리는 길을 비교해 보세요.
파이썬
def quat_from_axis_angle(u, a):
    u = u / np.linalg.norm(u)
    return np.r_[np.cos(a / 2), np.sin(a / 2) * u]        # (w, x, y, z)

def quat_to_R(q):
    w, x, y, z = q
    return np.array([[1 - 2*(y*y + z*z), 2*(x*y - w*z), 2*(x*z + w*y)],
                     [2*(x*y + w*z), 1 - 2*(x*x + z*z), 2*(y*z - w*x)],
                     [2*(x*z - w*y), 2*(y*z + w*x), 1 - 2*(x*x + y*y)]])

def slerp(q0, q1, s):                       # 구 위의 가장 짧은 길
    d = q0 @ q1
    if d < 0:
        q1, d = -q1, -d                     # q와 -q는 같은 자세
    if d > 0.9995:
        q = q0 + s * (q1 - q0)
        return q / np.linalg.norm(q)
    W = np.arccos(d)
    return (np.sin((1 - s) * W) * q0 + np.sin(s * W) * q1) / np.sin(W)

def euler_to_R(phi, th, psi):
    return Rz(psi) @ Ry(th) @ Rx(phi)

# 짐벌 락: θ = 90°이면 φ − ψ만 남는다
A = euler_to_R(np.radians(40), np.radians(90), np.radians(10))
B = euler_to_R(np.radians(60), np.radians(90), np.radians(30))
print(np.allclose(A, B))                    # True

해 볼 것

  • [짐벌]에서 피치를 천천히 90°로 올려 보세요. 바깥 고리(요)와 안쪽 고리(롤)의 회전축이 점점 가까워지다 겹칩니다. 오른쪽 표시가 ‘잠김’으로 바뀌어요.
  • 잠긴 상태에서 [요 +30°]와 [롤 +30°]를 번갈아 눌러 보세요. 오일러 숫자는 다르게 바뀌는데 행렬 R과 쿼터니언은 같은 값을 오갑니다.
  • [보간 비교]로 바꾸고 [재생]을 누르세요. 왼쪽 드론은 세 각을 따로 보간하고, 오른쪽은 slerp로 보간합니다. 출발과 도착 자세는 같은데, 기수 끝이 그리는 길과 아래 ‘실제로 돈 각도’가 크게 다릅니다. [잠김 근처]는 반대 경우예요. 숫자로는 φ와 ψ가 90°씩 바뀌는데 실제로는 7°만 돕니다.

핵심

숫자 세 개로 3D 회전을 적으면 어딘가에서 반드시 특이점이 생깁니다. 사람에게 보여 줄 땐 오일러 각을, 계산할 땐 회전 행렬이나 쿼터니언을 쓰세요. 두 자세 사이는 slerp로 가장 짧게 잇습니다.

3

회전으로 계산하는 제어기: 기하 제어

2D 페이지 식 (10)을 떠올려 보세요. 원하는 가속도에 중력을 더한 방향이 추력이 향해야 할 방향이었습니다. 3D에서도 똑같아요. 위치 제어기가 원하는 가속도 acmd를 내면, 거기에 g를 더한 방향이 원하는 b₃입니다. 기수 방향(요)을 하나 정하면 나머지 두 축이 외적으로 정해져서 원하는 자세 Rd가 통째로 나와요. 오일러 각을 거치지 않습니다.

자세 오차도 회전 그대로 계산합니다. Rd⊤R은 “지금 자세에서 원하는 자세까지 남은 회전”이에요. 이걸 회전축 u와 각도 α로 바꾸면, u축으로 α에 비례하는 토크를 거는 PD가 됩니다. 이 방식을 기하 제어(SO(3) 위의 제어, Lee·Leok·McClamroch 2010)라고 하고, 뒤집히든 공중제비를 돌든 특이점이 없어요.

비교 대상은 흔히 쓰는 오일러 각 PD입니다. 원하는 오일러 각과 지금 오일러 각의 차이를 그대로 롤·피치·요 토크로 써요. 호버 근처에선 둘이 거의 같지만, 크게 기울면 오일러 각의 차이는 실제 남은 회전과 다른 방향을 가리키고, 피치 90° 근처에선 숫자가 순간이동합니다.

원하는 가속도 → 원하는 자세와 추력
(7)
  1. 1원하는 위쪽 축. 2D 페이지 식 (10)의 3D판이에요.
  2. 2나머지 두 축. cψ = (cos ψ, sin ψ, 0)은 원하는 기수 방향이에요. 외적 두 번으로 서로 수직인 세 축이 완성됩니다.
  3. 3추력 크기. 지금 기체의 위쪽 성분만큼만 냅니다. 아직 덜 기울었으면 덜 밀어서 엉뚱한 방향으로 가속하지 않게 해요.
자세 오차와 토크
(8)
  1. 1남은 회전을 축 × 각도로. 쿼터니언으로 바꾸면 바로 나옵니다. Lee 등의 원 논문은 sin α · u를 쓰는데, 작은 각도에선 같고 180° 가까이에선 이 실습처럼 α를 쓰는 편이 빨리 돌아와요.
  2. 2회전 PD + 자이로 보상. ωd는 공중제비처럼 원하는 자세가 움직일 때의 피드포워드예요. 토크는 믹서로 모터 네 개가 됩니다.
비교: 오일러 각 PD
(9)
  1. 1각도 차이를 기체 축의 회전인 것처럼 씁니다. 호버 근처에서만 맞는 가정이에요. 피치가 90°를 지나면 φ와 ψ가 0°에서 180°로 뛰고, 남은 회전과 다른 축으로 토크가 걸립니다.
핵심위치 루프는 가속도를, 가속도는 b₃를, b₃와 요는 Rd를 정합니다. 오차도 Rd⊤R이라는 회전 그대로 계산하니 자세가 어디에 있든 같은 식이 통해요.
파이썬
from scipy.spatial.transform import Rotation as Rot
G, M = 9.81, 0.027
J = np.diag([1.4e-5, 1.4e-5, 2.2e-5])

def geometric_control(p, v, R, w, ref, kp=6.0, kd=4.2, kR=400.0, kw=36.0):
    a = ref.acc + kp * (ref.pos - p) + kd * (ref.vel - v)   # 원하는 가속도
    t = a + np.array([0, 0, G])
    b3 = t / np.linalg.norm(t)                             # 추력이 향할 방향
    c = np.array([np.cos(ref.yaw), np.sin(ref.yaw), 0])
    b2 = np.cross(b3, c); b2 /= np.linalg.norm(b2)
    Rd = np.column_stack([np.cross(b2, b3), b2, b3])       # 원하는 자세
    f = M * t @ R[:, 2]                                    # 지금 위쪽 성분만큼
    eR = Rot.from_matrix(Rd.T @ R).as_rotvec()             # 남은 회전 = 축 × 각도
    ew = w - R.T @ Rd @ ref.omega
    tau = J @ (-kR * eR - kw * ew) + np.cross(w, J @ w)
    return f, tau                                          # → 믹서(모터 4개)

def mixer(f, tau, d=0.0325, c=0.006):                      # X자 배치, 앞오른쪽부터
    pos = [(d, -d), (-d, -d), (-d, d), (d, d)]
    spin = [1, -1, 1, -1]
    return [f / 4 + tau[0] * y / (4 * d * d) - tau[1] * x / (4 * d * d)
            + tau[2] * s / (4 * c) for (x, y), s in zip(pos, spin)]

  • [뒤로 뒤집힌 채 놓기]는 피치 170°에서 시작합니다. 기하 제어는 0.3초 만에 바로 서는데, 오일러 PD는 숫자상 ‘롤 180°, 요 180°’로 보이는 자세를 롤과 요로 풀려다 바닥에 떨어져요.

핵심

기하 제어는 원하는 가속도에서 원하는 자세를 행렬로 만들고, 남은 회전을 축과 각도로 바꿔 토크를 겁니다. 오일러 각을 거치지 않으니 크게 기울거나 뒤집혀도 같은 식이 통해요. 레이싱 드론처럼 크게 기우는 기체에는 사실상 필수입니다.

2부

대회 맛보기: 게이트 여섯 개, 한 바퀴

자율 드론 레이싱은 사각형 게이트를 정해진 순서로 빠르게 통과하는 경기입니다. 2023년 취리히대학교의 Swift가 사람 챔피언들을 이겼고, 2025년 아부다비 A2RL에서는 TU Delft 팀의 드론이 최정상급 사람 선수를 이겼어요. 2026년 1월 두 번째 시즌의 사람 대 AI 결승에서는 한국의 김민찬 선수가 근소하게 이겼습니다. 여기서는 1부의 기하 제어와 2D 페이지의 최소 스냅 궤적만으로 한 바퀴를 돌아 보고, 실제 대회까지 무엇이 더 필요한지 정리합니다.

4

규칙, 기록, 그리고 세 가지 작전

경기장은 24 m × 14 m × 6 m 실내, 게이트는 안쪽 1.5 m 정사각형 여섯 개입니다. 기체는 출발점 위에서 떠 있다가 출발 신호와 함께 게이트 1부터 6까지 차례로 통과하고, 게이트 1을 한 번 더 지나면 한 바퀴예요. 게이트는 정해진 방향(바닥의 화살표)으로 통과해야 하고, 프레임에 닿으면 실격입니다. 옆으로 비껴가면 통과로 치지 않아서 다시 돌아와야 해요.

작전은 세 가지를 준비했습니다. 직선 PD는 다음 게이트 너머를 향해 PD로 날아가는 가장 단순한 방법이에요. 게이트에 비스듬히 들어가면 프레임에 걸립니다. 두 점 겨냥은 게이트 앞 1.5 m 지점을 먼저 노리고, 줄이 맞으면 게이트를 관통하는 점을 노려요. 아래 편집기의 코드가 바로 이 작전이고, 고쳐서 다시 날릴 수 있습니다. 최소 스냅 + 기하 제어는 모든 게이트를 정면으로 지나는 궤적을 미리 짜고 피드포워드로 따라갑니다.

궤적 작전에서 남는 질문은 “얼마나 빨리 돌 것인가”예요. 총시간 T를 줄이면 빨라지지만, 필요한 추력과 기울기 속도가 커져 어느 순간 기체가 따라가지 못합니다. 규정을 추력/무게 3.6 이하, 기울기 속도 12 rad/s 이하로 정하면, 지키는 T와 못 지키는 T 사이를 반씩 좁혀 가는 이분 탐색으로 가장 빠른 랩을 찾을 수 있어요. 열두 번이면 0.01초 단위까지 좁혀집니다.

def gate_check(g, p0, p1):                  # 이번 칸에 게이트를 지났나
    s0, s1 = g.n @ (p0 - g.c), g.n @ (p1 - g.c)
    if not (s0 < 0 <= s1):
        return None
    x = p0 + (p1 - p0) * s0 / (s0 - s1) - g.c   # 면 위의 교차점
    u = np.cross([0, 0, 1], g.n)
    inside = abs(u @ x) < g.w / 2 and abs(x[2]) < g.w / 2
    return 'pass' if inside else 'miss'

def feasible(T):                            # 규정을 지키는 궤적인가
    traj = min_snap_3d(knots, T)             # 2D 페이지의 최소 스냅을 세 축에
    tw, wr = traj.limits()                   # 추력/무게, 기울기 속도의 최댓값
    return tw <= 3.6 and wr <= 12.0

lo, hi = 4.0, 30.0                          # lo는 안 되고 hi는 되는 시간
for _ in range(12):                          # 이분 탐색
    mid = (lo + hi) / 2
    if feasible(mid):
        hi = mid
    else:
        lo = mid
print(f"가장 빠른 랩: {hi:.2f} s")
