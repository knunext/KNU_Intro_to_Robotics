명령을 넣으면, 몸은 어디로 갈까

운동 모델은 질문 하나에 답하는 함수입니다. 지금 상태가 이렇고 이런 명령을 넣었을 때, 잠깐 뒤에는 어떤 상태가 될까. 베이즈 필터의 예측 단계도, 경로 계획기의 확장 단계도, PID 실험용 시뮬레이터도 모두 이 함수를 부릅니다.

바퀴 두 개짜리 TurtleBot, 바퀴 네 개짜리 자동차, Crazyflie 같은 쿼드로터, 그리고 F-16급 제트기까지 네 가지 몸을 차례로 다룹니다. 앞의 둘은 속도를 바로 정하는 운동학 모델, 뒤의 둘은 힘으로 가속도를 정하는 동역학 모델이에요. 장마다 식, 파이썬 코드, 직접 조종해 볼 수 있는 시뮬레이터가 있습니다.

운동학: 속도를 바로 정하는 몸

바퀴 달린 로봇은 바닥을 붙잡고 굴러가서, 모터 명령이 거의 그대로 속도가 됩니다. 그래서 힘과 질량을 몰라도 ‘속도를 넣으면 위치가 나온다’는 운동학 모델로 충분해요. 대신 바퀴가 옆으로 미끄러지지 않는다는 제약 때문에, 갈 수 있는 방향이 정해져 있습니다.

1

모든 운동 모델의 모양

어떤 몸이든 운동 모델은 같은 꼴입니다. 몸의 상태 x를 정하고(위치, 방향, 필요하면 속도까지), 우리가 넣을 수 있는 입력 u를 정한 뒤, 상태가 시간에 따라 어떻게 변하는지를 미분방정식 ẋ = f(x, u)로 씁니다. 컴퓨터는 연속 시간을 다룰 수 없으니 짧은 시간 Δt마다 끊어서 다음 상태를 계산해요. 이게 적분입니다.

가장 단순한 몸은 바퀴 로봇을 점 하나로 본 유니사이클입니다. 상태는 (x, y, θ), 입력은 전진 속도 v와 회전 속도 ω. 문제는 Δt 동안 θ가 계속 변한다는 거예요. 스텝을 시작할 때의 방향으로 곧장 가면(오일러) 원 대신 옆으로 밀린 다각형이 됩니다. 구간 가운데의 방향을 쓰면(중점) 훨씬 낫고, v와 ω가 일정하다면 원호를 그대로 따라가는 정확한 식도 있어요. 베이즈 필터 실습의 운동 모델이 중점 방식이었습니다.

동역학 모델에서는 적분 방법이 더 중요해집니다. 상태에 속도가 들어가고 그 속도가 위치에 따라 바뀌는 용수철에 오일러를 쓰면, 스텝마다 에너지가 조금씩 늘어서 가만히 둬도 진동이 커져요. 속도를 먼저 갱신하고 새 속도로 위치를 갱신하는 반암시적 오일러는 순서만 바꿨는데 에너지가 거의 보존됩니다. MuJoCo의 기본 적분기가 이 계열이에요. 4차 룽게-쿠타(RK4)는 한 스텝에 f를 네 번 계산하는 대신 아주 정확합니다.

핵심운동 모델의 꼴, 그리고 시간을 쪼개 계산하는 세 가지 방법
  1. 상태가 시간에 따라 변하는 규칙. 운동 모델은 결국 이 함수 f 하나이고, 지금 상태와 명령을 넣으면 “지금 어느 쪽으로 얼마나 빨리 변하는지”를 돌려줍니다.
  2. 오일러는 구간이 시작할 때의 방향 θ로 곧장 나갑니다. Δt 동안 방향이 바뀌는 걸 무시하니 원을 돌 때 바깥으로 밀려요.
  3. 중점은 구간 가운데쯤의 방향을 씁니다. 바뀌는 방향을 반쯤 반영해서 오차가 훨씬 작아요(Δt²에 비례).
  4. v/ω는 원의 반지름 R입니다. v와 ω가 일정하면 로봇은 정확히 원호를 그리니, 이 식은 Δt가 커도 오차가 없어요.
  5. 용수철(ẍ = −x)에서는 속도를 먼저 갱신하고 그 새 속도 v′로 위치를 옮깁니다. 순서 하나 바꿨는데 에너지가 보존돼요.
파이썬
import numpy as np

def step_euler(s, v, w, dt):
    x, y, th = s
    return np.array([x + v*np.cos(th)*dt,
                     y + v*np.sin(th)*dt,
                     th + w*dt])

def step_midpoint(s, v, w, dt):
    x, y, th = s
    m = th + w*dt/2              # 구간 가운데의 방향
    return np.array([x + v*np.cos(m)*dt,
                     y + v*np.sin(m)*dt,
                     th + w*dt])

def step_exact(s, v, w, dt):
    x, y, th = s
    if abs(w) < 1e-9:              # 직진이면 오일러가 정확
        return step_euler(s, v, w, dt)
    R, th2 = v / w, th + w*dt    # 반지름 R인 원호를 그대로
    return np.array([x + R*(np.sin(th2) - np.sin(th)),
                     y - R*(np.cos(th2) - np.cos(th)),
                     th2])

def spring_euler(x, v, dt):
    return x + v*dt, v - x*dt

def spring_semi_implicit(x, v, dt):
    v = v - x*dt                 # 속도 먼저
    x = x + v*dt                 # 새 속도로 위치
    return x, v

해 볼 것

  • 유니사이클에서 Δt를 0.05초로 두면 세 방법이 거의 겹칩니다. 0.5초로 늘리면 오일러의 다각형이 원에서 옆으로 밀려나요. 원호 방식은 Δt와 상관없이 원 위에 있습니다.
  • [용수철]로 바꾸고 [20바퀴]를 눌러 보세요. 오일러는 나선으로 풀려 화면 밖으로 나가고, 반암시적 오일러는 Δt = 0.5에서도 닫힌 타원 위에 머뭅니다.
  • RK4는 반지름이 1보다 아주 조금 작아집니다. 에너지를 아주 조금씩 잃는 쪽으로 틀려요. 표의 반지름 열을 보세요.

핵심

운동 모델은 ‘식’과 ‘적분 방법’ 두 부분으로 되어 있습니다. 식이 맞아도 적분이 거칠면 시뮬레이션은 틀려요. 특히 동역학 모델에서 오일러는 에너지를 만들어 내서 시뮬레이션이 폭주할 수 있습니다. 그래서 물리 시뮬레이터는 Δt를 1~2 ms로 작게 잡고 반암시적 방법을 씁니다. 이 페이지의 2부 시뮬레이터들도 1~4 ms 스텝의 반암시적 오일러로 돌아가요.

바퀴 두 개: 차동 구동

TurtleBot3는 좌우 바퀴를 따로 돌리고 앞뒤의 볼 캐스터로 균형을 잡습니다. 조향 장치가 없으니 방향은 두 바퀴의 속도 차이로 바꿔요. 두 바퀴가 같은 속도면 직진, 반대 방향이면 제자리 회전, 그 사이면 원호를 그립니다.

바퀴가 미끄러지지 않으면 로봇은 늘 어떤 점을 중심으로 도는데, 이 점을 순간 회전 중심(ICC)이라고 합니다. ICC는 항상 바퀴 축을 연장한 선 위에 있어요. 바퀴는 옆으로 움직일 수 없으니, 바퀴가 그리는 원의 중심은 바퀴 축 방향에 있을 수밖에 없거든요. 같은 이유로 로봇은 옆으로 게걸음을 칠 수 없습니다. 이렇게 ‘속도에 걸린 제약’을 비홀로노믹 제약이라고 부르고, 경로 계획에서 차동 구동 로봇을 점처럼 다루면 안 되는 이유이기도 해요.

ROS에서는 로봇에 /cmd_vel로 (v, ω)를 보내고, 로봇 펌웨어가 아래 역변환으로 바퀴 속도를 계산합니다. 엔코더로 잰 바퀴 속도에 정변환을 적용하면 오도메트리가 돼요.

핵심바퀴 두 개의 속도가 로봇의 움직임이 되는 식
  1. 윗줄은 두 바퀴에 똑같이 r/2를 곱해 더합니다. 즉 평균이 전진 속도 v예요. 둘 다 앞으로 빨리 돌수록 빨라집니다.
  2. 아랫줄은 부호가 반대라서 차이만 남깁니다. 같은 속도면 ω = 0이라 직진, 반대 방향이면 제자리 회전이에요.
  3. 거꾸로 쓰면 /cmd_vel을 바퀴 명령으로 바꾸는 식. 돌려면 바깥 바퀴는 ωb/2만큼 빠르게, 안쪽 바퀴는 그만큼 느리게 돌립니다.
  4. 순간 회전 중심(ICC)까지의 거리. ω → 0이면 무한대(직진), v = 0이면 0(제자리 회전)이에요.

TurtleBot3 Burger: 바퀴 반지름 r = 0.033 m, 바퀴 사이 거리 b = 0.160 m

파이썬
R_WHEEL, TRACK = 0.033, 0.160    # TurtleBot3 Burger [m]

def wheels_to_twist(wl, wr):
    v = R_WHEEL * (wr + wl) / 2      # 평균 → 전진 속도
    w = R_WHEEL * (wr - wl) / TRACK  # 차이 → 회전 속도
    return v, w

def twist_to_wheels(v, w):           # /cmd_vel → 바퀴 명령
    wl = (v - w * TRACK / 2) / R_WHEEL
    wr = (v + w * TRACK / 2) / R_WHEEL
    return wl, wr

def step(s, wl, wr, dt):
    v, w = wheels_to_twist(wl, wr)
    return step_exact(s, v, w, dt)   # 1장의 원호 적분

해 볼 것

  • ICC(주황 점)가 늘 바퀴 축 연장선 위에 있는 걸 보세요. 두 바퀴 속도를 서로 가깝게 할수록 ICC가 멀어지고 원이 커집니다. 차이가 0이 되면 ICC는 무한히 멀어져 직진이 돼요.
  • [제자리 회전]에서는 ICC가 로봇 중심에 옵니다. 이때 v = 0이지만 바퀴는 둘 다 돌고 있어요.
  • [직접 운전]으로 바꿔 로봇을 오른쪽으로 30 cm 옮겨 보세요. 옆으로는 갈 수 없어서, 돌고 가고 다시 돌아야 합니다. 평행 주차와 같은 문제예요.

핵심

차동 구동은 (v, ω) 두 입력으로 세 개의 상태 (x, y, θ)를 움직입니다. 입력이 상태보다 적으니 모든 방향으로 바로 움직일 수는 없지만, 움직임을 이어 붙이면 어디든 갈 수 있어요. 제자리 회전이 되는 덕분에 이 몸은 계획하기 쉬운 편입니다.

행렬로 보기바퀴 두 개가 움직임이 되기까지

위의 식 네 줄은 사실 행렬 곱셈 두 번입니다. 바퀴 속도를 로봇의 (v, ω)로, 다시 그걸 지도 위의 속도로 바꾸는 거예요. 행렬에 벡터를 곱하는 건 두 가지로 읽을 수 있습니다. 열로 읽으면 “입력 하나하나가 결과에 보태는 몫을 모두 더한 것”, 행으로 읽으면 “출력 하나를 계산하는 공식”이에요.

단계를 넘기면 그 단계에서 쓰는 칸이 강조되고, 그 칸들이 만든 숫자가 아래 그림의 어느 화살표가 되는지 같은 색으로 보여 줍니다. 슬라이더를 움직이면 칸의 숫자와 그림이 함께 바뀌어요.

바퀴 네 개: 애커만 조향

자동차는 뒷바퀴로 밀고 앞바퀴를 꺾어 방향을 바꿉니다. 여기서도 바퀴는 옆으로 미끄러지지 않아야 하니, 네 바퀴 모두의 축 연장선이 한 점에서 만나야 해요. 뒷바퀴 두 개는 꺾이지 않으니 회전 중심은 뒷바퀴 축 연장선 위에 있고, 앞바퀴 두 개는 각자 그 점을 향하도록 서로 다른 각도로 꺾여야 합니다. 안쪽 바퀴가 바깥쪽보다 더 많이 꺾이는 이 배치를 애커만 조향 기하라고 합니다. 1810년대 마차 바퀴 연결 장치에서 온 이름이에요.

계산할 때는 보통 앞뒤 바퀴를 하나씩으로 합친 자전거 모델을 씁니다. 가운데 앞바퀴의 조향각 δ 하나만 있으면 회전 반지름이 R = L / tan δ로 정해지고, 실제 좌우 바퀴 각도는 그 R에서 역산하면 돼요. 차동 구동과 가장 큰 차이는 제자리 회전이 안 된다는 것입니다. 조향각에 한계 δmax가 있으니 최소 회전 반지름이 생기고, 이 제약이 경로 계획을 훨씬 어렵게 만들어요. 그래서 자동차용 계획에는 Dubins나 Reeds-Shepp 곡선, Hybrid A* 같은 방법을 씁니다.

핵심자전거 모델과 애커만 조향각
  1. 회전 속도에 v가 곱해져 있습니다. 멈추면(v = 0) 핸들을 아무리 돌려도 방향이 바뀌지 않아요. 차동 구동과의 가장 큰 차이.
  2. 1 m 갈 때 방향이 몇 rad 바뀌는지, 곧 회전 반지름의 역수 1/R. 조향 δ는 이 값만 정합니다.
  3. 조향각에 한계가 있으니 이보다 작은 원은 그릴 수 없어요. 자동차 경로 계획이 어려운 이유.
  4. 안쪽 바퀴는 회전 중심에 더 가까워서(R − W/2) 더 많이 꺾입니다. 네 바퀴의 축이 한 점에서 만나게 하는 조건이에요.

승용차 기준: 축간거리 L = 2.7 m, 윤거 W = 1.6 m, 최대 조향 δmax = 35°. R은 왼쪽 회전이 +인 부호 있는 값.

파이썬
L, W = 2.7, 1.6                  # 축간거리, 윤거 [m]
D_MAX = np.radians(35)

def step(s, v, delta, dt):
    delta = np.clip(delta, -D_MAX, D_MAX)
    w = v * np.tan(delta) / L    # 자전거 모델
    return step_exact(s, v, w, dt)

def ackermann_angles(delta):
    """가상 앞바퀴 각 → 실제 좌우 앞바퀴 각"""
    R = L / np.tan(delta)        # 부호 포함 (왼쪽 회전 +)
    left  = np.arctan(L / (R - W/2))
    right = np.arctan(L / (R + W/2))
    return left, right

해 볼 것

  • 조향을 끝까지 꺾고 출발해 보세요. 차가 그리는 원이 점선으로 표시된 최소 회전 원과 같습니다. 이보다 작게 도는 방법은 없어요.
  • [평행 조향]을 켜 보세요. 좌우 앞바퀴가 같은 각도로 꺾이면 바퀴 축 연장선(가는 선)이 한 점에서 만나지 않습니다. 실제 차라면 한쪽 바퀴가 옆으로 끌리며 타이어가 닳아요.
  • [후진]으로 조향을 꺾은 채 움직이면 같은 원을 거꾸로 돕니다. 후진을 섞어야 좁은 곳에서 방향을 바꿀 수 있는 이유예요.

핵심

차동 구동과 애커만은 같은 유니사이클 식을 쓰지만, 애커만은 ω가 v에 묶여 있습니다(ω = v tan δ / L). 멈춘 채로는 돌 수 없고, 아무리 꺾어도 Rmin보다 작게 돌 수 없어요. 운동 모델의 제약이 곧 경로 계획의 제약이 됩니다.

행렬로 보기열이 하나뿐인 자동차

자동차의 식을 차동 구동과 같은 꼴로 써 보면 둘의 차이가 한눈에 보입니다. 행렬의 열 개수는 따로따로 고를 수 있는 움직임의 개수예요. 열이 둘이면 평면을, 열이 하나면 직선 하나를 덮습니다.

2부

동역학: 힘으로 움직이는 몸

공중에 뜬 몸은 붙잡을 바닥이 없습니다. 모터가 정하는 건 속도가 아니라 힘이고, 힘은 질량으로 나뉘어 가속도가 되며, 가속도를 두 번 적분해야 위치가 나와요. 상태에 속도가 들어가야 하고, 입력이 위치에 닿기까지 적분이 두 번 끼어 있으니 손으로 조종하기 어렵습니다. 여기서 PID 같은 되먹임 제어가 필요해집니다.

4

쿼드로터, 위아래로만

쿼드로터 동역학의 첫걸음은 고도 하나만 보는 것입니다. 기울어지지 않는다고 치면 남는 건 고등학교 물리예요. 네 프로펠러의 추력 합 T가 위로, 중력 mg가 아래로 작용하고, 그 차이를 질량으로 나눈 게 수직 가속도입니다. Crazyflie 2.1은 27 g이고 모터 네 개의 최대 추력 합이 약 0.58 N이라, 떠 있는 데만 최대 추력의 45% 정도가 듭니다.

제어기는 PID를 ‘원하는 가속도’로 계산한 뒤 추력으로 바꾸는 꼴로 씁니다. T = m(g + a). 이렇게 하면 중력 보상(피드포워드) m·g가 따로 드러나고, 게인이 질량과 무관해져서 기체를 바꿔도 같은 게인을 쓸 수 있어요. Crazyflie 펌웨어의 위치 제어기도 이 구조입니다. 미분항은 오차를 미분하지 않고 측정한 속도 vz에 걸었는데, 목표가 갑자기 바뀌어도 출력이 튀지 않게 하는 흔한 방법이에요.

핵심고도 하나만 보는 쿼드로터와 PID
  1. 힘 = 질량 × 가속도. 추력은 속도가 아니라 가속도를 정합니다. 손으로 고도를 맞추기 어려운 이유예요.
  2. 중력. 제어기에서 g를 미리 더해 주는 것이 중력 보상(피드포워드)이고, 그 덕에 PID는 남는 차이만 다루면 됩니다.
  3. P: 지금 얼마나 떨어져 있나. 멀수록 세게 당깁니다.
  4. I: 그동안 쌓인 오차. 배터리가 약해져 모자란 힘처럼, 모델이 틀린 만큼을 천천히 메웁니다.
  5. D: 지금 얼마나 빨리 다가오나. 브레이크 역할로 출렁임을 막아요. 오차 대신 측정한 속도에 걸어서 목표가 바뀌어도 튀지 않습니다.

Crazyflie 2.1: m = 0.027 kg, Tmax ≈ 0.58 N, mg ≈ 0.265 N, 모터 지연 τ ≈ 30 ms

파이썬
M, G, T_MAX = 0.027, 9.81, 0.58

class AltitudePID:
    def __init__(self, kp=6.0, ki=1.0, kd=3.5):
        self.kp, self.ki, self.kd = kp, ki, kd
        self.i = 0.0

    def update(self, z_ref, z, vz, dt):
        e = z_ref - z
        a = self.kp*e + self.ki*self.i - self.kd*vz
        T = M * (G + a)              # 중력 보상 + PID
        T_sat = np.clip(T, 0.0, T_MAX)
        if T_sat == T:               # 포화 중엔 적분 멈춤
            self.i += e * dt         # (anti-windup)
        return T_sat

def plant(z, vz, T, dt):             # m z̈ = T − m g
    az = T / M - G
    vz += az * dt
    z  += vz * dt
    return z, vz

5

쿼드로터, 옆으로도: 기울여야 간다

이제 옆에서 본 평면 쿼드로터입니다. 상태는 위치 (y, z), 기울기 φ, 그리고 각각의 속도까지 여섯 개. 입력은 왼쪽과 오른쪽 모터 추력 T₁, T₂ 두 개예요(실제로는 모터 네 개지만 옆에서 보면 좌우 한 쌍씩 합쳐집니다). 추력은 늘 기체 위쪽으로만 나오니, 옆으로 가려면 먼저 기울어야 합니다. 기울면 추력의 일부가 옆으로 향하고, 대신 위로 받치는 힘이 줄어요.

입력 두 개로 상태 여섯 개를 다루려면 순서가 필요합니다. 그래서 제어기를 두 겹으로 쌓아요. 바깥 루프(100 Hz)는 위치 오차로 ‘원하는 가속도’를 계산하고, 그 가속도를 내려면 몇 도 기울어야 하는지 정합니다. 안쪽 루프(500 Hz)는 그 기울기를 맞추도록 두 모터의 추력 차이를 정해요. 이 캐스케이드 구조는 안쪽 루프가 바깥보다 충분히 빨라야 성립합니다. 바깥 루프는 ‘기울기는 명령하면 금방 맞춰진다’고 가정하고 계산하니까요. Crazyflie 펌웨어도 위치 → 자세 → 각속도의 세 겹 캐스케이드로 되어 있습니다.

핵심옆에서 본 쿼드로터와 두 겹 제어기
  1. 추력은 늘 기체 위 방향으로만 나옵니다. 기울기 φ가 그 힘을 옆(sin)과 위(cos)로 나눠요. 옆으로 가려면 먼저 기울어야 하는 이유.
  2. 두 모터의 차이 × 팔 길이 = 기체를 돌리는 힘(토크). 기울기는 이걸로만 바꿀 수 있습니다.
  3. 바깥 루프(100 Hz): 원하는 가속도 (ay, az)를 내려면 몇 도 기울어야 하고 추력은 얼마여야 하나.
  4. 안쪽 루프(500 Hz): 그 기울기에 빨리 맞추는 PD. ωn이 안쪽 루프의 빠르기이고, 바깥보다 충분히 빨라야 합니다.

def dynamics(s, T1, T2):            # ṡ = f(s, u)
    y, z, phi, vy, vz, w = s
    T = T1 + T2
    ay = -T * np.sin(phi) / M
    az =  T * np.cos(phi) / M - G
    aw = (T2 - T1) * ARM / I_XX
    return np.array([vy, vz, w, ay, az, aw])

def outer_loop(ref, s, kp=5.0, kd=3.5):    # 100 Hz
    y, z, phi, vy, vz, w = s
    ay = kp*(ref[0] - y) - kd*vy
    az = kp*(ref[1] - z) - kd*vz
    phi_des = np.clip(-np.arctan2(ay, G + az), -0.52, 0.52)
    T = M * (G + az) / np.cos(phi)
    return phi_des, T

def inner_loop(phi_des, T, s, wn=22.0):   # 500 Hz
    phi, w = s[2], s[5]
    alpha = wn**2*(phi_des - phi) - 2*0.8*wn*w
    d = I_XX * alpha / ARM                # T2 − T1
    return T/2 - d/2, T/2 + d/2

행렬로 보기모터 두 개가 힘의 방향이 되기까지

평면 쿼드로터의 동역학은 행렬 두 개로 정리됩니다. 모터 두 개의 추력을 “얼마나 세게, 얼마나 돌리게”로 바꾸는 믹서 행렬, 그리고 기체 기준의 추력을 세계 기준의 힘으로 돌려놓는 회전행렬이에요. 회전행렬의 두 열이 곧 기체의 옆 방향과 위 방향이라는 것만 알면, 쿼드로터가 왜 기울어야 움직이는지가 숫자로 보입니다.

6

제트기: 날개가 힘을 만든다

쿼드로터는 모터가 직접 기체를 들어 올리지만, 비행기는 엔진이 앞으로 밀기만 하고 뜨는 힘은 날개가 만듭니다. 날개가 공기를 받는 각도, 즉 받음각 α가 클수록 양력이 커지는데, 너무 커지면 공기 흐름이 날개에서 떨어져 양력이 갑자기 줄어요. 이게 실속입니다. 양력과 항력은 둘 다 동압 ½ρV²에 비례해서, 속도가 두 배면 같은 받음각에서 힘이 네 배가 됩니다.

여기서는 옆에서 본 세로 방향 운동만 다룹니다(롤과 요는 뺐어요). 각도가 셋 나오는 게 핵심입니다. 기수가 가리키는 방향 θ(피치), 실제로 날아가는 방향 γ(비행경로각), 그리고 둘의 차이인 받음각 α = θ − γ. 조종사는 엘리베이터로 기수를 들어 α를 키우고, 커진 양력이 비행 방향 γ를 위로 휘게 합니다. 기수를 든다고 바로 올라가는 게 아니라, 받음각을 거쳐서 올라가는 거예요. 플랩은 날개 뒷부분을 내려 같은 α에서 양력을 키우는 대신 항력도 늘리고, 이착륙 때 씁니다.

F-16은 일부러 정적으로 불안정하게 설계됐습니다(이완 안정성, RSS). 기수가 들리면 더 들리려는 쪽이라 사람 손으로는 못 날지만, 그만큼 꼬리 날개가 작아도 되고 기동이 날렵해요. 대신 컴퓨터가 초당 수십 번 엘리베이터를 고쳐 잡는 플라이 바이 와이어(FBW)가 필수입니다. 이 시뮬레이터의 FBW는 조종간을 ‘피치 각속도 명령’으로 해석하는 PI 제어기에, 속도에 따라 게인을 바꾸는 게인 스케줄링과 받음각 제한기를 붙인 단순한 버전이에요.

핵심제트기의 세로 운동: 각도 셋과 힘 넷
  1. 받음각: 기수가 가리키는 방향(θ)과 실제로 날아가는 방향(γ)의 차이. 양력의 손잡이이고, 22°를 넘으면 실속합니다.
  2. 동압: 속도의 제곱에 비례해요. 속도가 두 배면 같은 받음각에서 양력도 항력도 네 배.
  3. 양력은 비행 방향 γ를 위로 휘게 합니다. 기수를 들면 바로 오르는 게 아니라 α → L → γ를 거쳐서 올라가요.
  4. 음수면 α가 커질 때 기수를 내려 되돌립니다(정적 안정). F-16은 일부러 양수로 만들어 FBW가 필요해요.

F-16급 값: m = 10 t, S = 27.9 m², c = 3.45 m, Tmax = 76 kN (애프터버너 127 kN). 롤과 요는 뺐어요.

def jet_step(s, throttle, de, dt):
    V, gam, theta, q, x, h = s
    rho  = 1.225 * np.exp(-h / 8500)
    qbar = 0.5 * rho * V**2              # 동압
    alpha = theta - gam                  # 받음각
    CL = CL_ALPHA * alpha                # (실속 전까지)
    CD = CD0 + K * CL**2
    L, D = qbar*S*CL, qbar*S*CD
    T = T_MAX * throttle
    Cm = CM0 + CM_ALPHA*alpha + CM_Q*q*C/(2*V) + CM_DE*de
    M_pitch = qbar * S * C * Cm

    V_dot   = (T*np.cos(alpha) - D - MASS*G*np.sin(gam)) / MASS
    gam_dot = (T*np.sin(alpha) + L - MASS*G*np.cos(gam)) / (MASS*V)
    q_dot   = M_pitch / I_YY
    return [V + V_dot*dt, gam + gam_dot*dt,
            theta + q*dt, q + q_dot*dt,
            x + V*np.cos(gam)*dt, h + V*np.sin(gam)*dt]

def fbw(stick, q, alpha, qbar, st, dt):
    q_cmd = 0.35 * stick                 # 조종간 = 피치 각속도 명령
    if alpha > ALPHA_MAX - 0.1:          # 받음각 제한기
        q_cmd = min(q_cmd, 2.5*(ALPHA_MAX - alpha))
    e = q_cmd - q
    st.i += e * dt
    k = QBAR_REF / qbar                  # 게인 스케줄링
    return np.clip(k*(2.0*e + 3.0*st.i), -DE_MAX, DE_MAX)

핵심

제트기의 입력은 위치에 닿기까지 길을 멀리 돕니다. 엘리베이터 → 피치 모멘트 → 받음각 → 양력 → 비행경로 → 고도. 각 단계의 반응 속도가 크게 달라서(받음각은 1초, 속도와 고도는 수십 초), 실제 자동조종 장치도 쿼드로터처럼 빠른 안쪽 루프 위에 느린 바깥 루프를 쌓는 캐스케이드로 만듭니다.

한눈에 비교

고정익 제트기V, γ, θ, q, x, h (세로 운동)스로틀, 엘리베이터, 플랩동역학 + 공기력멈춰서 뜨기, 실속 각 넘기피치 각속도 루프 위의 경로·속도 루프, 게인 스케줄링
  1. 운동 모델은 ẋ = f(x, u)와 적분 방법의 짝이다. 식이 같아도 Δt와 적분 방법에 따라 결과가 달라진다.
  2. 바퀴 로봇은 운동학으로 충분하다. 바닥이 미끄러짐을 막아 주는 대신 갈 수 있는 방향을 제한하고, 이 제약이 경로 계획으로 이어진다.
  3. 날거나 헤엄치는 몸은 동역학이 필요하다. 입력이 힘이라 위치까지 적분이 두 번 끼고, 사람 손보다 되먹임 제어가 먼저다.
  4. 입력이 상태보다 적으면 순서가 생긴다. 쿼드로터는 기울어야 가고, 비행기는 받음각을 거쳐야 오른다. 캐스케이드 제어는 그 순서를 루프로 옮긴 것이다.

이 페이지의 쿼드로터와 제트기는 수업용으로 많이 단순화했습니다. 실제 Crazyflie를 3D로 다루려면 자세를 회전행렬이나 쿼터니언으로 표현하고 모터 네 개의 추력과 반토크를 넣으면 되는데, 식의 뼈대는 여기와 같아요. 직접 만든 MuJoCo 시뮬레이터에 같은 식과 PID 게인을 옮겨 놓고 실기체와 비교해 보는 것도 좋은 과제가 됩니다.
