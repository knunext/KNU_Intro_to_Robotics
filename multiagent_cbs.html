따로 찾고, 부딪히면 가르고, 다시 찾는다

로봇 한 대의 길은 A*로 찾았어요. 그런데 물류창고에서는 수백 대가 같은 통로를 씁니다. 각자 최단 경로로 출발하면 교차로에서 부딪히죠. 이번 단원은 여러 로봇의 경로를 서로 부딪히지 않게 한꺼번에 찾는 다중 로봇 경로 계획(MAPF)입니다.

1부에서는 시간을 한 축으로 더한 시공간 A*, 순서대로 길을 예약하는 우선순위 계획, 그리고 이 단원의 주인공 충돌 기반 탐색(CBS)을 직접 돌려 봐요. 2부에서는 같은 생각이 아마존 물류창고, 드론 쇼, 위성 군집에서 어떻게 쓰이는지 봅니다.

1장부터 시작

로봇마다 다음 목적지가 생길 때 다른 로봇이 예약한 시공간 칸을 피해 길을 찾습니다.

1부

원리: 시간 위에서 길을 나눠 쓴다

경로 계획 단원의 A*는 칸만 봤어요. 로봇이 여럿이면 “어느 칸”에 “언제”가 붙습니다. 같은 칸이라도 시간이 다르면 함께 쓸 수 있으니까요. 1부의 모든 알고리즘은 이 시공간 위의 탐색입니다.

1

혼자 찾은 길은 부딪힌다

문제를 정확히 적어 봅시다. 지도는 그래프 G = (V, E)이고, 격자라면 칸이 정점, 상하좌우로 붙은 칸 사이가 간선이에요. 로봇 k대가 있고 로봇 i는 출발 칸 si에서 목표 칸 gi로 갑니다. 시간은 0, 1, 2, … 한 칸씩 흐르고, 한 시각에 로봇은 이웃 칸으로 한 칸 이동하거나 제자리에서 기다립니다. 목표에 도착한 로봇은 그 자리에 계속 머문다고 봐요.

부딪힘, 곧 충돌은 두 가지입니다. 같은 시각에 같은 칸에 있으면 정점 충돌, 한 시각 사이에 두 로봇이 서로 자리를 맞바꾸면 간선 충돌이에요. 맞바꾸는 경우는 매 시각 위치만 비교해서는 안 보이니 따로 검사해야 합니다.

잘 푼 정도는 보통 비용 합(SOC), 곧 로봇마다 목표에 마지막으로 도착한 시각을 모두 더한 값으로 잽니다. 가장 늦은 로봇의 도착 시각인 메이크스팬을 쓰기도 해요. 어려운 이유도 바로 보입니다. 로봇 전체를 하나의 상태로 묶으면 상태 수가 칸 수의 k제곱이라, 로봇 열 대만 돼도 일반 A*로는 엄두가 안 나요.

경로: 한 시각에 한 칸 이동하거나 기다린다
(1)
  1. 1출발. 시각 0의 위치는 출발 칸 si예요.
  2. 2이동. N(v)는 v와 간선으로 붙은 이웃 칸들. 격자라면 상하좌우 최대 네 칸입니다.
  3. 3기다림. 제자리에 있는 것도 한 시각을 쓰는 행동이에요. 혼자일 땐 쓸모없지만 여럿일 땐 기다림이 길을 양보하는 유일한 방법입니다.
두 가지 충돌
(2)
  1. 1정점 충돌. 같은 시각 t에 같은 칸. 실습에서는 ⟨i, j, 칸, t⟩로 적어요.
  2. 2간선 충돌. t − 1에서 t로 넘어가는 사이에 두 로봇이 자리를 맞바꿈. 두 시각의 위치 모두 겹치지 않지만 통로 한가운데서 정면으로 부딪힙니다.
무엇을 줄일까
(3)
  1. 1로봇 하나의 비용. 그 뒤로는 목표를 떠나지 않는 첫 시각. 목표에 들렀다가 비켜 주러 나가면 다시 돌아온 시각이 비용이에요.
  2. 2비용 합(SOC). 이 단원의 기본 목적 함수. 전체 로봇이 쓴 시간의 합이라 에너지·처리량과 가깝습니다.
  3. 3메이크스팬. 가장 늦은 로봇의 도착 시각. 드론 쇼처럼 모두 함께 끝나야 할 때 씁니다.
한꺼번에 풀면 상태가 폭발한다
(4)
  1. 1결합 상태 수. 로봇마다 |V|개 칸 중 하나에 있으니 곱하면 |V|k. 8×8 격자에 열 대면 약 1018개예요.
  2. 2한 상태의 자식 수. 로봇마다 행동이 최대 다섯 가지(네 방향 + 기다림)라 5k. 열 대면 한 번 펼칠 때마다 거의 천만 개를 만듭니다.

  • ‘복도 맞교환’에서 두 로봇이 정확히 몇 시각에 마주치는지 확인하고, 옆 칸 하나로 어떻게 비켜 줄 수 있을지 생각해 보세요.
  • 로봇 수를 늘려 가며 오른쪽의 결합 상태 수가 어떻게 변하는지 보세요. 한 대 늘 때마다 몇 배가 되나요?

핵심

MAPF의 상태는 ‘칸’이 아니라 ‘칸과 시각’입니다. 혼자 찾은 최단 경로는 서로를 모르니 부딪히고, 전부 묶어 찾으면 상태가 폭발해요. 2장과 3장은 이 둘 사이의 길을 찾습니다.

2

시간을 한 축으로: 시공간 A*와 우선순위 계획

한 대만 계획하되 다른 로봇이 언제 어디 있는지를 피해야 한다면, 상태를 (칸, 시각)으로 늘리면 됩니다. 이웃은 다음 시각의 이웃 칸과 다음 시각의 제자리, 비용은 시각 그 자체예요. 휴리스틱은 다른 로봇을 무시한 목표까지의 최단 거리이고, 목표에서 거꾸로 BFS 한 번이면 모든 칸의 값을 얻습니다. 이게 시공간 A*예요.

하나 조심할 것은 끝나는 조건입니다. 목표 칸에 도착했더라도 그 뒤 시각에 그 칸이 막혀 있으면 머물 수 없어요. 그래서 “목표 칸에 걸린 제약 중 가장 늦은 시각보다 뒤에 도착했는가”까지 확인합니다.

가장 단순한 다중 로봇 방법은 우선순위 계획(PP)입니다. 로봇에 순서를 매기고, 앞 로봇의 경로를 시공간 칸 단위로 예약해 둔 뒤 다음 로봇이 시공간 A*로 그 예약을 피해 가요. 아주 빠르지만 두 가지 약점이 있습니다. 순서에 따라 결과가 달라지고, 해가 있는데도 못 찾는 경우가 있어요. 앞 로봇은 뒤 로봇을 위해 비켜 주지 않으니까요.

시공간 A*: 비용은 시각, 휴리스틱은 BFS 거리
(5)
  1. 1지나온 비용 g = t. 이동이든 기다림이든 한 시각에 비용 1이라 지금 시각이 곧 지나온 비용이에요.
  2. 2남은 비용 추정. 그래프 위 최단 거리 dG. 다른 로봇을 무시했으니 실제보다 크지 않아 허용적입니다.
  3. 3끝나는 조건. 목표에 있으면서 목표 칸에 걸린 제약 ⟨gi, t′⟩보다 늦게 도착해야 그 자리에 계속 머물 수 있어요.
우선순위 계획: 앞 순서의 경로를 예약으로
(6)
  1. 1순서 σ. σ(1)이 가장 먼저 계획하는 로봇. 순서가 k!가지이니 다 해 볼 수는 없어요.
  2. 2예약표. 앞 로봇들이 차지한 (칸, 시각)과 반대 방향 이동, 그리고 도착 뒤 목표 칸을 영원히. 뒤 로봇에겐 움직이는 장애물입니다.
st_astar.py · 시공간 A*
import heapq

def st_astar(grid, s, g, h, vcon, econ, max_t):
    """vcon: {(칸, t)}, econ: {(u, v, t)} 금지 목록
    h: 목표에서 거꾸로 BFS 한 거리"""
    last_g = max([t for (v, t) in vcon if v == g], default=-1)
    openq = [(h[s], 0, s, None)]
    parent, seen = {}, {(s, 0)}
    while openq:
        f, t, v, par = heapq.heappop(openq)
        parent[(v, t)] = par
        if v == g and t > last_g:          # 식 (5)의 끝나는 조건
            return extract(parent, (v, t))
        if t >= max_t:
            continue
        for w in [v] + grid.neighbors(v):   # 기다림 + 이웃
            nt = t + 1
            if (w, nt) in seen or (w, nt) in vcon or (v, w, nt) in econ:
                continue
            seen.add((w, nt))
            heapq.heappush(openq, (nt + h[w], nt, w, (v, t)))
    return None

def extract(parent, node):
    path = []
    while node is not None:
        path.append(node[0])
        node = parent[node]
    return path[::-1]

def prioritized(grid, starts, goals, order, horizon):
    vres, eres, paths = set(), set(), {}
    for i in order:                          # 식 (6)의 σ
        p = st_astar(grid, starts[i], goals[i], bfs(grid, goals[i]),
                     vres, eres, horizon)
        if p is None:
            return None                      # 이 순서로는 실패
        paths[i] = p
        for t in range(horizon + 1):         # 시공간 칸 예약
            v = p[min(t, len(p) - 1)]        # 도착 뒤엔 목표에 머묾
            vres.add((v, t))
            if 0 < t < len(p):
                eres.add((p[t], p[t - 1], t))  # 맞교환 금지
    return paths

3

충돌 기반 탐색(CBS)

CBS(Sharon 외, 2015)의 생각은 단순합니다. 일단 각자 최단 경로로 계획하고, 부딪히는 곳이 나오면 그때 둘로 나눈다. 로봇 A와 B가 시각 3에 칸 (2,1)에서 부딪힌다면, 해는 둘 중 하나예요. “A는 시각 3에 (2,1)에 없다” 아니면 “B는 시각 3에 (2,1)에 없다”. 두 경우를 각각 자식 노드로 만들고, 제약을 받은 로봇 한 대만 시공간 A*로 다시 계획합니다.

그래서 탐색이 두 층이에요. 위층은 제약 트리(CT)를 비용이 작은 노드부터 펼치는 최우선 탐색이고, 노드 하나는 제약 목록, 로봇별 경로, 비용 합을 가집니다. 아래층은 로봇 한 대의 시공간 A*예요. 결합 공간을 통째로 탐색하는 대신 충돌이 난 곳에서만 갈라지니, 로봇이 많아도 서로 덜 엇갈리면 금방 끝납니다.

최적인 이유도 두 줄이에요. 어떤 올바른 해든 두 로봇이 그 칸에 동시에 있을 수 없으니 두 자식 중 적어도 하나의 제약을 만족합니다. 그리고 제약은 더해지기만 하니 자식 비용은 부모보다 작아지지 않아요. 그래서 비용 순으로 꺼낸 첫 충돌 없는 노드가 최적해입니다.

충돌 하나를 두 제약으로 나눈다
(7)
  1. 1왼쪽 자식. 로봇 i에게 “시각 t에 v 금지”를 더하고 i만 다시 계획해요.
  2. 2오른쪽 자식. 같은 제약을 로봇 j에게. 간선 충돌이면 각자의 이동 방향을 금지합니다.
  3. 3노드 비용. 그 노드의 경로들로 계산한 SOC. 위층은 이 값이 가장 작은 노드부터 꺼냅니다.
왜 최적인가
(8)
  1. 1해를 잃지 않는다. 충돌 없는 해 Π*에서는 두 로봇이 동시에 v에 있을 수 없으니, 적어도 한 자식의 제약 집합 안에 Π*가 남아요.
  2. 2비용은 커지기만 한다. 제약이 늘면 최단 경로는 같거나 길어집니다. 그래서 먼저 꺼낸 충돌 없는 노드보다 싼 해는 트리 어디에도 없어요.
cbs.py · 위층 탐색 (아래층은 2장의 st_astar)
import heapq, itertools

def sum_cost(paths):
    return sum(len(p) - 1 for p in paths)            # 식 (3) SOC

def constraint_for(a, c):
    kind, i, j, where, t = c
    if kind == "vertex":
        return (a, "v", where, t)                     # a는 시각 t에 where 금지
    u, v = where if a == i else where[::-1]
    return (a, "e", (u, v), t)                        # a는 t에 u→v 이동 금지

def cbs(k, low_level):
    tie = itertools.count()
    paths = [low_level(i, []) for i in range(k)]     # 각자 최단 경로
    openq = [(sum_cost(paths), next(tie), [], paths)]
    while openq:
        cost, _, cons, paths = heapq.heappop(openq)  # 비용이 가장 작은 노드
        c = first_conflict(paths)                    # 1장의 충돌 검사
        if c is None:
            return paths                             # 충돌 없음 → 최적
        for a in (c[1], c[2]):                       # 식 (7): 둘로 나눈다
            new = cons + [constraint_for(a, c)]
            p = low_level(a, [x for x in new if x[0] == a])
            if p is None:
                continue                             # 이 가지엔 해가 없음
            child = paths[:a] + [p] + paths[a + 1:]  # a만 다시 계획
            heapq.heappush(openq, (sum_cost(child), next(tie), new, child))
    return None

  • ‘가운데 비상구’를 한 단계씩 진행하며, 제약이 하나씩 쌓일 때 B의 경로가 어떻게 비상구로 밀려나는지 보세요. 2장에선 어떤 순서로도 못 풀던 문제예요.
  • 트리의 아무 노드나 눌러 그 노드의 경로표를 보세요. 같은 비용의 노드가 여럿일 때 CBS가 무엇부터 펼치는지 확인하세요.
  • ‘교차로 넷’에서 자식 노드의 비용이 부모와 같은 경우와 1 커지는 경우를 찾아보세요. 4장의 카디널 충돌로 이어집니다.

핵심

CBS는 결합 공간 대신 충돌의 공간을 탐색합니다. 각자 계획하고, 충돌 하나를 두 제약으로 나누고, 제약받은 한 대만 다시 계획해요. 충돌이 적으면 빠르고, 같은 비용의 충돌이 많으면 트리가 지수적으로 커집니다.

더 빠르게: 충돌을 골라 나누고, 조금 양보한다

CBS가 느려지는 전형은 “나눴는데 비용이 그대로인” 노드가 줄줄이 생길 때예요. 한 로봇에게 제약을 줘도 같은 길이의 다른 길로 돌아가면 비용이 안 늘고, 그런 노드가 모두 펼쳐질 때까지 탐색이 끝나지 않습니다. 그래서 어떤 충돌부터 나눌지가 중요해요.

로봇 하나의 최단 경로를 전부 겹쳐 놓은 것을 MDD(다중값 결정도)라고 합니다. 시각마다 “최단 경로라면 있을 수 있는 칸들”이에요. 충돌 시각의 MDD 폭이 1이면 그 칸을 피하는 최단 경로가 없다는 뜻이라, 제약을 주는 순간 비용이 1 늘어요. 두 로봇 모두 그러면 카디널 충돌, 한쪽만이면 세미 카디널, 둘 다 아니면 논 카디널입니다. 카디널 충돌부터 나누면 트리의 하한이 빨리 올라가요. 이게 ICBS(Boyarski 외, 2015)의 핵심입니다.

최적을 조금 양보하는 방법도 있어요. 비용이 하한의 w배 이내인 노드들(focal) 가운데 충돌이 가장 적은 노드를 먼저 펼치면, 해의 비용은 최적의 w배를 넘지 않으면서 훨씬 빨리 끝납니다. ECBS(Barer 외, 2014)는 이 focal 탐색을 위층과 아래층 모두에 써요. 이 페이지의 실습은 위층에만 적용한 단순한 버전입니다.

MDD와 카디널 충돌
(9)
  1. 1최단 경로 묶음. Πi*는 지금 제약 아래 로봇 i의 최단 경로 전부. 시각 t의 MDD는 그 경로들이 t에 지나는 칸의 집합이에요.
  2. 2폭이 1이면 우회로가 없다. 두 로봇 모두 충돌 시각에 폭이 1이면 어느 쪽에 제약을 줘도 비용이 오르니, 두 자식 모두 비용이 커집니다.
focal: 하한의 w배 안에서 충돌이 적은 것부터
(10)
  1. 1하한. 열린 노드 중 가장 작은 비용. 최적해의 비용은 이보다 작을 수 없어요.
  2. 2focal 목록. 비용이 하한의 w배 이하인 노드. 이 안에서는 비용 대신 남은 충돌 수로 고릅니다.
  3. 3보장. 꺼낸 노드의 비용이 늘 w · LB 이하이고 LB ≤ SOC*이니, 찾은 해는 최적의 w배를 넘지 않아요.
icbs.py · MDD와 충돌 분류
def mdd(grid, s, g, allowed, c):
    F = [{s}]                                  # 앞으로: t에 닿을 수 있는 칸
    for t in range(1, c + 1):
        F.append({w for v in F[-1] for w in [v] + grid.neighbors(v)
                  if allowed(v, w, t)})
    L = [set() for _ in range(c + 1)]
    L[c] = {g} & F[c]                          # 뒤로: c에 목표에 닿는 칸만
    for t in range(c - 1, -1, -1):
        L[t] = {v for v in F[t]
                if any(w in L[t + 1] and allowed(v, w, t + 1)
                       for w in [v] + grid.neighbors(v))}
    return L

def bottleneck(L, cost, kind, t):
    if t > cost:                               # 이미 도착해 쉬는 중
        return True
    if kind == "vertex":
        return len(L[t]) == 1                  # 식 (9)
    return len(L[t]) == 1 and len(L[t - 1]) == 1
focal.py · 위층에서 노드 고르기
def pick(open_nodes, w):
    lb = min(n.cost for n in open_nodes)       # 식 (10)의 LB
    focal = [n for n in open_nodes if n.cost <= w * lb]
    return min(focal, key=lambda n: (n.n_conflicts, n.cost))

def choose_conflict(node, mdds):
    def rank(c):
        kind, i, j, where, t = c
        a = bottleneck(mdds[i], node.cost_of(i), kind, t)
        b = bottleneck(mdds[j], node.cost_of(j), kind, t)
        return (-(a + b), t)                   # 카디널 → 세미 → 논, 이른 것부터
    return min(node.conflicts, key=rank)

아마존 물류창고: 끝나지 않는 MAPF

아마존은 2012년 로봇 회사 키바 시스템즈를 7억 7,500만 달러에 사들여 아마존 로보틱스로 바꿨어요. 키바식 창고에서는 사람이 선반을 찾아 걷지 않습니다. 바닥의 로봇이 선반 밑으로 들어가 선반째 들어 올려 피킹 스테이션의 작업자에게 가져오고, 작업자가 물건을 꺼내면 선반을 다시 제자리에 갖다 놓아요. 아마존은 2025년 7월 배치한 로봇이 100만 대를 넘었다고 밝혔고, 함께 공개한 생성형 AI 모델 DeepFleet이 로봇 이동 효율을 10% 높인다고 했습니다. 실제 경로 계획 알고리즘은 공개하지 않았어요.

창고 문제는 목적지에 도착하면 바로 다음 목적지가 생기는 평생(lifelong) MAPF입니다. 아마존 로보틱스가 후원한 2023년 대회 League of Robot Runners가 바로 이 문제였어요. 로봇이 최대 1만 대, 한 시각마다 계획 시간 1초. 흔한 접근은 몇 시각마다 앞쪽 몇 걸음만 충돌 없이 다시 푸는 롤링 호라이즌(RHCR)과, 이 실습에서 쓰는 토큰 패싱(Ma 외, 2017)입니다.

토큰 패싱은 2장의 우선순위 계획을 끝없이 돌리는 방법이에요. 다음 목적지가 필요한 로봇이 차례로 ‘토큰’을 받아, 다른 로봇이 예약한 시공간 칸을 피해 경로를 찾고 예약합니다. 선반 자리와 스테이션 같은 끝점엔 목적지일 때만 들어가고, 도착한 로봇은 다음 경로를 받을 때까지 그 끝점을 예약해 둬요. 그래서 기다릴 곳이 늘 있고, 데드락 없이 영원히 돌아갑니다. 처리량은 리틀의 법칙으로 읽어요.

리틀의 법칙으로 처리량 읽기
(11)
  1. 1처리량 λ. 시각당 끝낸 피킹 수. 실습에선 100시각당 건수로 보여 줘요.
  2. 2로봇 수 N. 시스템 안에 늘 N개의 일이 돌고 있다고 보면 리틀의 법칙 그대로입니다.
  3. 3기다린 시간. 혼잡해서 생긴 지연. 로봇을 늘리면 이 항이 커져서 λ가 N만큼 늘지 않아요.
  4. 4스테이션 상한. 스테이션 M개가 일 하나에 평균 Tst씩 묶이면 처리량은 이 값을 넘을 수 없어요. 로봇이 아무리 많아도요.
lifelong.py · 토큰 패싱의 한 시각
def tick(t, robots, res, endpoints):
    for r in rotate(robots, t):                 # 토큰을 차례로 넘긴다
        if r.arrive_t > t or r.busy(t):
            continue                            # 아직 가는 중이거나 작업 중
        goal = r.next_goal(free=endpoints - res.taken_by_others(r))
        if goal is None:
            res.hold(r, r.pos, t)               # 끝점에서 대기: 아무도 안 들어옴
            continue
        res.release(r)                          # 이 로봇의 끝점 예약 해제
        path = st_astar(r.pos, goal, res, t,    # 남의 예약 + 남의 끝점 피하기
                        no_enter=endpoints - {r.pos, goal})
        res.reserve(r, path, t, hold_end=True)  # 경로와 도착 뒤 끝점 예약
        r.arrive_t = t + len(path) - 1

핵심

평생 MAPF에선 한 번의 최적해보다 시간당 처리량이 목표예요. 처리량은 결국 병목이 정합니다. 스테이션이 막히면 로봇을 늘려도 대기만 길어지고, 통로가 막히면 길을 나눠 쓰는 규칙이 처리량을 바꿔요.

드론 쇼와 드론 레이싱: 누가 어디로, 그리고 어떻게

밤하늘에 수백 대의 드론이 그림을 바꿔 그리는 드론 쇼도 MAPF예요. 다만 1부와 두 가지가 다릅니다. 첫째, 대형의 어느 점에 어느 드론이 가든 상관없어서 목표를 배정하는 문제가 먼저 나와요. 둘째, 공간이 격자가 아니라 연속입니다.

배정은 비용 행렬의 헝가리안 알고리즘으로 O(n3)에 정확히 풀려요. 재미있는 사실은 거리의 제곱 합을 최소로 배정하고 모든 드론이 동시에 출발해 같은 속도 비율로 직선 비행하면, 출발점과 도착점 간격이 드론 반지름의 2√2배 이상인 한 서로 부딪히지 않는다는 것이에요(CAPT, Turpin 외, 2014). 두 직선 경로가 엇갈리면 배정을 바꿔 제곱 합을 더 줄일 수 있기 때문입니다.

장애물이 있거나 간격이 좁으면 3차원 격자 위에서 CBS를 돌려요. 1부의 코드에서 이웃만 여섯 방향으로 바꾸면 됩니다. 드론 레이싱처럼 여러 대가 같은 게이트를 차례로 통과할 때도 같아요. 다른 드론의 궤적을 시공간 예약으로 두고 시공간 계획을 하며, 시간이 연속이면 칸 대신 안전 구간을 예약하는 SIPP나 연속 시간 CBS(CCBS)를 씁니다. 부딪힘 판정은 두 점의 최근접 거리 계산 하나예요.

누가 어디로: 거리 제곱 합을 최소로
(12)
  1. 1비용 행렬의 칸. 드론 i가 대형 점 j로 갈 때의 거리 제곱. n × n 행렬에서 행과 열이 겹치지 않게 n칸을 골라 합을 최소로 하는 문제예요.
  2. 2헝가리안 알고리즘. 행과 열에 잠재값을 더하고 빼며 0인 칸으로 완전 매칭을 만들어 갑니다. 파이썬에선 scipy의 함수 하나예요.
언제 가장 가까워지나: 최근접 거리
(13)
  1. 1처음 상대 위치. 두 드론 위치의 차이 벡터.
  2. 2상대 속도. 동시에 출발해 함께 도착하니 진행률 s ∈ [0, 1]을 시간처럼 씁니다.
  3. 3가장 가까운 순간. 거리 제곱을 s로 미분해 0으로 놓으면 나오는 값을 [0, 1]로 자른 것. 내적 두 번이면 끝나요.
  4. 4최근접 거리. 이 값이 안전거리보다 작으면 충돌입니다. 위성의 근접 검사도 같은 계산이에요.
show.py · 배정과 최근접 검사
import numpy as np
from scipy.optimize import linear_sum_assignment

P = np.array(starts)                         # (n, 3) 지금 위치
Q = np.array(targets)                        # (n, 3) 다음 대형
C = ((P[:, None, :] - Q[None, :, :]) ** 2).sum(axis=2)   # 식 (12)
rows, cols = linear_sum_assignment(C)        # 헝가리안, O(n³)

def closest(p0, p1, q0, q1):
    dp = p0 - q0                             # 처음 상대 위치
    dv = (p1 - p0) - (q1 - q0)               # 상대 속도
    s = 0.0 if dv @ dv < 1e-12 else np.clip(-(dp @ dv) / (dv @ dv), 0, 1)
    return np.linalg.norm(dp + s * dv), s    # 식 (13)

위성 군집: 궤도면이 엇갈리는 곳에서 만나지 않게

스타링크 위성은 2025년 12월부터 2026년 5월까지 여섯 달 동안 충돌 회피 기동을 20만 7,152번 했어요. 스페이스X는 충돌 확률이 1000만분의 3을 넘으면 피하는데, 업계에서 흔히 쓰는 1만분의 1보다 훨씬 보수적인 기준입니다. 운용 중의 회피는 궤도를 예측해 식 (13)과 같은 최근접 계산으로 위험한 만남을 찾고, 한 위성의 궤도를 조금 바꾼 뒤 다시 검사하는 반복이에요. 충돌을 찾고 제약을 걸어 다시 계획하는 CBS와 같은 고리입니다.

설계 단계에서도 같은 문제가 나와요. 같은 고도의 궤도면 여러 개는 지구 반대편 두 점에서 서로 엇갈립니다. 두 궤도면의 위성이 그 교차점을 거의 동시에 지나면 아슬아슬하죠. 위성은 모두 같은 속도로 도니, 궤도면마다 위성 배열을 조금 앞당기거나 늦추는 위상 하나로 이 만남을 피할 수 있어요. 워커 배치에서 이웃 궤도면의 위상 차를 정하는 매개변수 F가 바로 이 역할입니다.

여기서는 궤도면마다 위상을 5° 단위 슬롯에서 따로 고르는 문제로 바꿨어요. 로봇 = 궤도면, 경로 = 위상 슬롯, 충돌 = 교차점에서 가까운 만남. 아래층은 “금지되지 않은 가장 작은 슬롯”이라 한 줄이고, 위층은 3장의 CBS 그대로예요. 이 문제에선 같은 비용의 노드가 아주 많아서 최적 CBS의 트리가 2의 거듭제곱으로 불어나는 모습도 볼 수 있습니다.

교차점에서의 간격
(14)
  1. 1궤도면 p의 위상. 궤도면의 위성 전체를 같은 각도만큼 앞당겨요. 교차점의 궤도 위치 up는 기하로 정해집니다.
  2. 2궤도면 q의 위상. 두 궤도면의 위상 차만 간격을 바꿔요.
  3. 3위성 간격 S. 한 궤도면에 위성이 N기 고르게 있으면 S = 360°/N마다 같은 상황이 반복되니 나머지를 취합니다.
  4. 4충돌. 같은 교차점을 지나는 두 위성의 각도 차가 기준보다 작으면 충돌로 봐요. 실제 거리는 교차각에 따라 다르지만 여기선 이 근사로 충분합니다.

def low_level(forbidden, K):
    return next((d for d in range(K) if d not in forbidden), None)

def gap(node, phase, S):                    # 식 (14)
    r = ((node.u_p - phase[node.p]) - (node.u_q - phase[node.q])) % S
    return min(r, S - r)

def conflicts(nodes, slots, step, S, sep):
    phase = [d * step for d in slots]         # 슬롯 → 위상(도)
    return [n for n in nodes if gap(n, phase, S) < sep]

키바 시스템즈의 특허를 보면 구조가 1부와 놀랄 만큼 같아요. 중앙의 경로 계획 모듈이 길을 정해 주면, 로봇은 앞 구간을 예약 모듈에 요청해 확보한 뒤 움직입니다. 로봇 쪽은 거리를 세고 90°씩 돌고 바코드를 읽는 정도만 하면 돼요. 사람이 꼭 들어가야 할 때는 와이파이 송신기가 달린 Tech Vest를 입고, 로봇들은 그 위치를 피해 경로를 짭니다.

그래서 이 트윈은 5장 모델에 아래 규칙을 더했어요. 로봇이 방향을 가지니 상태가 (칸, 방향, 시각)으로 늘어나는데, 아마존 로보틱스가 후원한 League of Robot Runners의 회전 모델과 같은 방식입니다. 휴리스틱은 방향까지 포함해 목표에서 거꾸로 BFS 한 값이라 로봇 한 대만 보면 정확해요. 계획은 5장처럼 토큰 패싱이고, 대기열 앞자리가 비면 오는 중인 로봇의 목적지를 한 칸 당겨 다시 계획합니다.

def successors(v, th, t, floor, loaded, goal, under_pods):
    yield v, th, t + 1                             # 기다림
    yield v, (th + 1) % 4, t + 1                   # 오른쪽으로 90°
    yield v, (th + 3) % 4, t + 1                   # 왼쪽으로 90°
    w = floor.step(v, DIRS[th])                    # 바라보는 쪽으로 한 칸
    if w is None or not floor.allowed(v, w):       # 일방통행, 스테이션 대기열 규칙
        return
    if floor.is_pod_slot(w) and w != goal:
        if loaded or not under_pods:               # 포드를 든 로봇은 못 지나감
            return
    yield w, th, t + 1

고급 예제 2: 반도체 팹의 천장 반송(OHT)

반도체 팹에서 웨이퍼는 25장씩 FOUP(앞면이 열리는 밀폐 용기)에 담겨, 수백 단계의 공정을 거치며 장비에서 장비로 옮겨 다닙니다. 300 mm 팹의 자동 반송 시스템(AMHS)은 대부분 천장 레일을 달리는 OHT(overhead hoist transport)예요. 차량이 레일에 매달려 달리다가 장비의 로드 포트나 스토커 포트 바로 위에 멈추고, 벨트로 감아 내리는 호이스트로 FOUP을 내리거나 올립니다. 레일은 장비가 늘어선 베이 안을 도는 인트라베이 고리와 베이들을 잇는 인터베이 고리로 이루어지고, 레일 옆이나 아래에는 FOUP을 잠깐 맡겨 두는 STB(side track buffer)와 UTB(under track buffer) 선반이 달려 있어요.

MAPF로 보면 창고와 가장 다른 점은 추월이 안 된다는 것입니다. 레일은 일방통행이라 맞교환(간선 충돌)은 처음부터 생기지 않고 정점 충돌만 남아요. 대신 한 차량이 포트 위에서 FOUP을 내리는 10여 초 동안 그 칸이 막히고, 같은 레일 위의 뒤차들은 줄줄이 기다립니다. 시공간으로 보면 호이스트 중인 차량은 위로 솟은 기둥이고, 뒤차는 그 기둥을 돌아갈 길이 없어요. 그래서 이 문제는 보통 세 층으로 나눠 다룹니다. 어느 반송을 어느 차량에 맡길지 정하는 배차, 어느 레일로 갈지 정하는 경로, 실제로 부딪히지 않게 하는 블록 제어예요.

이 트윈의 생김새는 삼성전자, SK하이닉스, 마이크론 같은 메모리 회사와 OHT 제조사(다이후쿠, 무라타기계)가 공개한 클린룸 사진·영상, 그리고 특허와 논문에 나오는 특징을 따랐어요. 천장은 팬 필터 유닛(FFU) 격자이고, 바닥은 구멍 뚫린 이중 바닥입니다. 감광액이 단파장 빛에 반응하기 때문에 포토 베이만 노란 조명이에요. 장비 앞에는 로드 포트 두 개와 3색 신호등이 달렸고, 장비는 공정마다 모양이 다릅니다.

  • 포토: 코터·디벨로퍼 트랙과 노광 장비
  • 식각·증착: 육각 이송 챔버에 공정 챔버가 붙은 클러스터 장비
  • 확산: 키 큰 종형 퍼니스
  • 이온 주입: 분석 자석이 달린 긴 빔라인
  • CMP: 연마 패드가 도는 연마기
  • 세정: 배기 덕트가 천장까지 올라간 습식 세정대

베이 12개에 장비 72대, 로드 포트 132개, 인터베이의 UTB 24칸, 양 끝 스토커가 있고, 하얀 방진복 차림의 작업자들도 통로를 오갑니다. 실제 팹의 배치와 운영 규칙은 공개되지 않으니, 크기와 개수는 수업용으로 줄여 다시 구성한 모델이에요.

배차는 ‘가장 가까운 빈 차량’과 6장의 ‘헝가리안 일괄 배정’ 가운데, 경로는 ‘최단 거리’와 2장의 우선순위 계획을 레일에 옮긴 ‘시공간 예약’ 가운데 고를 수 있어요. 공정이 끝난 FOUP은 다음 공정 베이의 빈 로드 포트로 가고, 빈 포트가 없으면 가까운 UTB에 잠시 맡겨집니다. 실행층은 어느 쪽이든 같은 블록 제어예요. 다음 칸이 비어야 들어가고, 고리가 꽉 차면 다 같이 한 칸씩 움직입니다.

반송 시간을 쪼개 보기
(17)
  1. 1배차 대기. 요청이 생긴 뒤 차량이 정해질 때까지. 빈 차량이 모자라면 이 항이 커지고, 배차 규칙이 가장 크게 바꾸는 항이에요.
  2. 2빈 차 이동. 배차된 차량이 출발 포트까지 가는 시간. 레일이 일방통행이라 바로 옆 포트도 고리를 한 바퀴 돌아야 할 수 있어요.
  3. 3호이스트. 포트 위에 멈춰 FOUP을 내리고 올리는 시간. 집을 때와 내릴 때 두 번이고, 이 동안 그 칸은 막힙니다.
  4. 4막힘. 앞차 때문에 멈춘 시간. 추월이 안 되는 레일에서만 생기는 항으로, 경로 방식과 지름길 레일이 줄이려는 것이에요.
block.py · 블록 제어: 다음 칸이 비어야 들어간다
def tick(vehicles):
    occupied = {v.plan[0] for v in vehicles}
    moved, changed = set(), True
    while changed:                                  # 앞차가 빠지면 뒤차가 이어서 움직인다
        changed = False
        for v in vehicles:
            if v in moved or len(v.plan) < 2 or v.plan[1] == v.plan[0]:
                continue
            if v.plan[1] not in occupied:           # 다음 칸이 비어야만 들어간다
                occupied.discard(v.plan[0])
                occupied.add(v.plan[1])
                moved.add(v)
                changed = True
    for v in vehicles:                              # 꽉 찬 고리의 동시 전진은 생략
        if len(v.plan) < 2:
            continue
        if v in moved or v.plan[1] == v.plan[0]:    # 이동했거나 계획된 정지(호이스트)
            v.plan.pop(0)
        else:
            v.blocked += 1                          # 막힘: 남은 계획 전체가 한 틱 밀린다

핵심

추월이 안 되는 레일에서 MAPF는 ‘어느 길로’보다 ‘누가 언제 지나가느냐’의 문제가 됩니다. 그래서 배차, 경로, 블록 제어를 층으로 나눠 풀어요. 시공간 예약은 막힌 시간을 크게 줄이지만, 먼저 계획한 차량에게 늘 양보하는 탓에 평균 반송 시간은 오히려 늘 수 있습니다. 그리고 지름길 레일 같은 레이아웃이 알고리즘보다 큰 차이를 내기도 해요.
