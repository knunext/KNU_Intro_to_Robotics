두 팔이 서로 비켜 가는 길 찾기

RRT 팔 실습에서는 관절 두 개짜리 팔로 C-space를 직접 눈으로 봤습니다. 실제 로봇팔은 관절이 일곱 개고, 가사 로봇은 그런 팔이 두 개예요. 관절각 14개가 곧 C-space의 점 하나인데, 14차원은 그릴 수 없습니다. 그래도 알고리즘은 그대로예요.

연구실에서 가장 많이 쓰는 7자유도 팔인 Franka Panda 두 대를 책상에 나란히 놓고, 순기구학, 충돌 검사, 역기구학, 7차원 RRT, 14차원 양팔 계획을 차례로 만들어 봅니다. 오른쪽 그림은 페이지가 열릴 때 RRT-Connect로 실제로 계획한 경로예요.

팔을 계산할 수 있게 만들기

경로 계획기는 두 가지만 물어봅니다. 관절각이 이럴 때 팔은 어디 있나(순기구학), 그리고 그 자세가 무언가에 부딪히나(충돌 검사). 목표가 손 위치로 주어지면 하나가 더 필요해요. 손이 거기 있으려면 관절각이 얼마여야 하나(역기구학).

1

관절 일곱 개, 손 하나

팔은 링크와 관절이 번갈아 이어진 사슬입니다. 관절마다 좌표계를 하나씩 붙이면, ‘앞 좌표계에서 본 다음 좌표계의 위치와 방향’은 그 사이 링크의 모양(고정된 숫자)과 관절각 하나로 정해져요. 이걸 4×4 변환행렬로 쓰고 어깨부터 손끝까지 차례로 곱하면 손끝의 위치와 방향이 나옵니다. 그래픽스의 장면 그래프와 똑같은 계산이에요.

링크 모양을 숫자 세 개 (a, d, α)로 적는 약속이 DH 파라미터인데, 표를 직접 만들 일은 거의 없습니다. 제조사가 공개하고, MuJoCo 모델 파일이나 URDF에도 이미 들어 있어요. 여기서는 Franka가 공개한 값을 그대로 썼습니다. 중요한 건 이 계산의 결과가 관절각 7개 → 손 자세라는 함수라는 점입니다. 관절각 7개 묶음이 C-space의 점 하나고요.

핵심관절 하나의 변환과, 손끝까지 이어 곱하기
  1. 관절각 q가 들어가는 유일한 곳. 나머지 셋은 링크 모양(a, d, α)으로 정해진 상수라 표 한 장이면 끝입니다.
  2. 관절 순서대로 곱합니다. 앞에 곱해진 관절이 돌면 그 뒤에 붙은 모든 것이 함께 돌아요. q₁이 팔 전체를 돌리는 이유.
  3. 3×3 회전 부분: 세 열이 그 좌표계의 x, y, z축이 가리키는 방향. 손에서는 셋째 열이 손이 향하는 방향.
  4. 위치 부분: 그 좌표계의 원점, 손에서는 손끝의 위치.

import numpy as np
PI = np.pi
# (a_{i-1}, d_i, alpha_{i-1})
PANDA = [(0, 0.333, 0), (0, 0, -PI/2), (0, 0.316, PI/2),
         (0.0825, 0, PI/2), (-0.0825, 0.384, -PI/2),
         (0, 0, PI/2), (0.088, 0, PI/2)]

def link_T(a, d, al, q):
    ca, sa, cq, sq = np.cos(al), np.sin(al), np.cos(q), np.sin(q)
    return np.array([[cq,    -sq,     0,   a],
                     [sq*ca,  cq*ca, -sa, -sa*d],
                     [sq*sa,  cq*sa,  ca,  ca*d],
                     [0,      0,      0,   1]])

def fk(T_base, q):
    frames, T = [T_base], T_base
    for (a, d, al), qi in zip(PANDA, q):
        T = T @ link_T(a, d, al, qi)     # 차례로 곱한다
        frames.append(T)
    T = T @ link_T(0, 0.107, 0, 0)         # 플랜지
    T = T @ link_T(0, 0.1034, 0, -PI/4)    # 손끝
    frames.append(T)
    return frames    # 위치 T[:3, 3], 손 방향 T[:3, 2]

순기구학은 ‘변환을 차례로 곱하기’ 하나뿐입니다. 결과는 관절각 7개를 받아 손 자세를 돌려주는 함수이고, 플래너는 이 함수를 수만 번 부르면서 팔이 어디 있는지 확인해요. 그래서 빠르고 정확하게 짜는 게 중요합니다.

행렬로 보기4×4 행렬 아홉 장을 곱하면 손이 나온다

순기구학은 결국 4×4 행렬을 차례로 곱하는 일입니다. 행렬 한 장은 좌표계 하나를 담고 있어요. 어느 칸이 축의 방향이고 어느 칸이 위치인지, 관절각 q는 어느 칸에 들어가는지만 알면 행렬 곱셈이 “링크를 하나씩 이어 붙이는 것”으로 보입니다.

단계를 넘기면 그 단계에서 볼 칸이 색으로 강조되고, 3D 그림에서 같은 색 화살표가 그 칸들이 실제로 무엇인지 보여 줍니다. 칸에 마우스를 올리면 뜻이 나와요.

2

몸을 구슬로 감싸기

2관절 팔 실습에서는 링크가 선분이라 충돌 검사가 쉬웠습니다. 실제 팔은 굵은 3D 덩어리예요. 정확한 메시끼리 겹침을 검사하는 방법도 있지만 느려서, 경로 계획에서는 흔히 팔을 구 여러 개로 감싸고 구끼리, 구와 상자끼리만 검사합니다. 구 두 개가 겹치는지는 중심 사이 거리가 반지름 합보다 작은지 보면 되고, 구와 상자는 상자 안에서 구 중심에 가장 가까운 점까지의 거리를 보면 돼요.

여기서는 관절 원점 사이를 잇는 캡슐마다 반지름보다 촘촘하게 구를 깔아, 팔 하나를 구 24개로 감쌌습니다(바닥에 붙은 받침대는 빼고). 구 하나가 실제 팔보다 조금 크게 감싸니 보수적이에요. 검사가 ‘충돌 아님’이라고 하면 정말 안 부딪히지만, 아슬아슬하게 지나갈 수 있는 틈은 막혔다고 볼 수 있습니다. GPU로 수천 개 자세를 한꺼번에 검사하는 NVIDIA cuRobo 같은 최신 플래너도 이 구 근사를 씁니다.

두 팔이 있으면 검사가 세 종류가 됩니다. 각 팔과 장애물, 각 팔과 책상, 그리고 왼팔과 오른팔. 마지막 것 때문에 두 팔의 계획을 따로 떼어 생각할 수 없어요. 여기서는 단순하게 하려고 한 팔이 자기 몸에 부딪히는 자기 충돌은 빼고, 관절 한계로만 막았습니다.

핵심구로 감싼 몸의 충돌 검사
  1. 두 중심 사이 거리가 두 반지름의 합보다 작으면 겹칩니다. 구 두 개의 검사는 이 비교 하나예요.
  2. 축마다 구의 중심을 상자 범위 안으로 잘라 넣으면, 상자 안에서 구와 가장 가까운 점 p가 됩니다. 그 거리를 반지름과 비교.
  3. 책상 윗면이 z = 0이니, 구의 바닥(cz − r)이 0 아래로 내려가면 충돌.

한 자세 검사 비용(팔 2개, 상자 6개): 구 24 × 2 × (상자 6 + 책상 1) ≈ 340번, 왼팔 구 24 × 오른팔 구 24 ≈ 580번 → 거리 계산 약 900번. 플래너는 이걸 수천~수만 번 부릅니다.

def sphere_box_hit(c, r, bmin, bmax):
    p = np.clip(c, bmin, bmax)       # 상자 안 최근접점
    return np.sum((c - p)**2) < r*r

def arm_spheres(frames, caps):
    out = []
    for i, j, r in caps:             # 두 프레임 원점 사이 캡슐
        a, b = frames[i][:3, 3], frames[j][:3, 3]
        n = max(1, int(np.ceil(np.linalg.norm(b - a) / (0.9*r))))
        for t in np.linspace(0, 1, n + 1):
            out.append((a + (b - a)*t, r))
    return out

def is_free(qL, qR, boxes):
    SL = arm_spheres(fk(T_L, qL), CAPS)
    SR = arm_spheres(fk(T_R, qR), CAPS)
    for c, r in SL + SR:
        if c[2] - r < 0:                       # 책상
            return False
        if any(sphere_box_hit(c, r, *b) for b in boxes):
            return False
    for c1, r1 in SL:                          # 팔 대 팔
        for c2, r2 in SR:
            if np.sum((c1 - c2)**2) < (r1 + r2)**2:
                return False
    return True

3

손에서 관절로: IK와 남는 자유도

목표는 보통 ‘컵 위 10 cm에서 손을 아래로’처럼 손 자세로 주어집니다. 플래너는 C-space에서 일하니 목표도 관절각으로 바꿔야 해요. 이게 역기구학(IK)입니다. 7관절 팔은 식을 풀어 답을 바로 쓰기 어려워서, 숫자로 조금씩 다가가는 방법을 씁니다. 지금 손과 목표의 차이를 재고, ‘관절을 조금 움직이면 손이 얼마나 움직이는지’를 담은 야코비안 J로 그 차이를 줄이는 관절 변화를 구해 한 걸음 가는 걸 반복해요. 최적화의 경사하강과 같은 생각입니다.

J는 6×7이라 역행렬이 없으니 최소제곱으로 풉니다. 그냥 풀면 팔이 거의 다 펴진 특이 자세 근처에서 관절이 폭주해서, 작은 값 λ²을 더해 걸음을 누그러뜨리는 감쇠 최소제곱(DLS)을 써요. 손 위치 3개와 방향 3개를 맞추는 데 관절이 7개니 자유도가 하나 남습니다. 손을 그대로 둔 채 팔꿈치를 원을 그리며 돌릴 수 있다는 뜻이에요. 이 남는 방향(영공간)으로는 마음대로 움직여도 손이 안 흔들리니, 장애물을 피하거나 관절 한계에서 멀어지는 데 씁니다.

핵심감쇠 최소제곱 IK 한 걸음
  1. 손이 가야 할 만큼(위치 차이)과 돌아야 할 만큼(손 방향 차이)을 한 줄로 모은 오차.
  2. 관절 j를 돌렸을 때 손이 움직이는 속도(축 × 손까지의 거리)와 도는 축. 이걸 일곱 관절 모아 놓은 표가 야코비안 J.
  3. e를 만드는 관절 변화 중 가장 작은 것. J를 “거꾸로” 쓰는 계산입니다.
  4. 팔이 다 펴져 J가 납작해져도 Δq가 폭주하지 않게 하는 작은 쿠션. λ = 0.08.
  5. 손을 건드리지 않는 방향만 남기는 필터(영공간). 이 방향으로 팔꿈치만 돌립니다.

반복: q ← clip(q + Δq, 관절 한계), 오차 e가 충분히 작아질 때까지.

파이썬
def jacobian(F):                       # F = fk(...) 의 프레임들
    p = F[-1][:3, 3]
    J = np.zeros((6, 7))
    for j in range(7):
        z, o = F[j+1][:3, 2], F[j+1][:3, 3]
        J[:3, j] = np.cross(z, p - o)  # 손끝 선속도
        J[3:, j] = z                   # 손 각속도
    return J

def ik_step(q, p_goal, z_goal, q_pref, lam=0.08, k=0.3):
    F = fk(T_base, q)
    p, z = F[-1][:3, 3], F[-1][:3, 2]
    e = np.r_[p_goal - p, 0.5*np.cross(z, z_goal)]
    J = jacobian(F)
    J_pinv = J.T @ np.linalg.inv(J @ J.T + lam**2*np.eye(6))
    dq = J_pinv @ e
    N = np.eye(7) - J_pinv @ J         # 영공간 투영
    dq += N @ (k * (q_pref - q))
    return np.clip(q + dq, Q_MIN, Q_MAX)

IK는 ‘오차를 줄이는 방향으로 한 걸음’의 반복입니다. 답이 여러 개일 수도, 없을 수도 있고, 어디서 출발하느냐에 따라 다른 답에 도착해요. 7관절 팔의 남는 자유도는 손을 움직이지 않고 팔 모양을 바꾸는 데 쓸 수 있어서, 좁은 곳에서 팔을 다룰 때 큰 도움이 됩니다.

행렬로 보기야코비안: 관절 하나가 손에 주는 효과를 모은 표

위 실습의 IK는 매 반복마다 행렬 두 개를 씁니다. 야코비안 J는 “관절을 조금 돌리면 손이 어떻게 움직이나”를 관절마다 한 열씩 적은 6×7 표이고, J⁺는 그 표를 거꾸로 써서 “손을 이만큼 옮기려면 관절을 얼마나 돌려야 하나”를 계산합니다. 열이 일곱 개인데 손의 움직임은 여섯 숫자라서 하나가 남는데, 그게 팔꿈치 회전이에요.

2부

고차원 C-space에서 길 찾기

이제 재료가 다 모였습니다. 순기구학과 충돌 검사가 ‘이 점은 자유 공간인가’에 답하고, IK가 목표 점을 줍니다. RRT는 2관절 팔에서 했던 것과 한 줄도 다르지 않아요. 벡터가 2개에서 7개, 14개로 길어졌을 뿐입니다.

4

팔 하나: 7차원 RRT-Connect

출발 자세와 목표 자세가 7차원 공간의 두 점입니다. 관절 한계 안에서 무작위로 점을 뽑고, 트리에서 가장 가까운 노드부터 그 점을 향해 ε만큼 가 보고, 가는 길이 충돌 없으면 노드로 붙입니다. 가는 길은 관절 공간의 직선을 0.04 rad 간격으로 잘라 모두 검사해요. 2관절 실습에서 본 그대로입니다.

차원이 높아지면 두 가지가 달라집니다. 첫째, 공간이 넓어서 목표 근처에 우연히 닿기가 훨씬 어렵습니다. 목표 쪽으로 가끔 끌어당기는(목표 편향) 단일 트리 RRT가 좁은 틈 앞에서 오래 헤매는 이유예요. 양쪽에서 트리를 키워 서로를 향해 뻗는 RRT-Connect는 이 문제에 훨씬 강해서, MoveIt의 기본 플래너도 오랫동안 RRT-Connect였습니다. 둘째, 트리를 그릴 수 없습니다. 그래서 이 그림은 각 노드의 손끝 위치만 3D에 찍었어요. 그림자처럼 정보를 잃은 투영이라, 손끝 선이 서로 겹치거나 장애물을 지나는 것처럼 보여도 실제 7차원에서는 떨어져 있을 수 있습니다.

핵심7차원 C-space에서 쓰는 세 가지 계산
  1. C-space의 거리: 관절각 차이의 제곱합에 루트. “가장 가까운 노드”를 고를 때 노드마다 이 계산을 합니다.
  2. 가장 가까운 노드에서 표본 쪽으로 최대 ε만큼만 나아간 새 점(EXTEND).
  3. 그 한 걸음이 안전한지 보려고 검사하는 점의 수. 가장 많이 움직이는 관절이 정합니다.
EXTEND(T, q)
   qnear ← T에서 q에 가장 가까운 노드
   qnew  ← qnear에서 q 쪽으로 최대 ε
   qnear→qnew 직선을 0.04 rad 간격으로 검사 → 모두 자유면 T에 추가

RRT-Connect
   반복:  qrand ← 무작위 표본
          EXTEND(A, qrand) 로 qnew를 만들면
          B를 qnew 쪽으로 막힐 때까지 계속 EXTEND
          B가 qnew에 닿으면 → 두 트리를 이어 경로 완성
          A ↔ B 역할 바꾸기
파이썬
def edge_free(qa, qb, free, res=0.04):
    n = int(np.ceil(np.max(np.abs(qb - qa)) / res))
    return all(free(qa + (qb - qa)*t)
               for t in np.linspace(0, 1, n + 1)[1:])

def extend(T, q, free, eps=0.35):
    i = T.nearest(q)
    d = np.linalg.norm(q - T.q[i])
    q_new = q if d <= eps else T.q[i] + (q - T.q[i])*eps/d
    if not edge_free(T.q[i], q_new, free):
        return 'trapped', None
    return ('reached' if d <= eps else 'advanced'), T.add(q_new, i)

def rrt_connect(q_start, q_goal, free, max_iter=5000):
    A, B = Tree(q_start), Tree(q_goal)
    for _ in range(max_iter):
        q_rand = np.random.uniform(Q_MIN, Q_MAX)
        st, j = extend(A, q_rand, free)
        if st != 'trapped':
            while (r := extend(B, A.q[j], free))[0] == 'advanced':
                pass
            if r[0] == 'reached':
                return join(A, j, B, r[1])   # 두 트리를 잇는다
        A, B = B, A
    return None

RRT 계열은 차원에 거의 상관없이 같은 코드로 돌아갑니다. 바뀌는 건 충돌 검사가 비싸지고 공간이 넓어진다는 것뿐이에요. 그래서 고차원에서는 양쪽에서 자라는 RRT-Connect처럼 ‘목표를 빨리 찾는’ 구조와, 찾은 뒤 다듬는 후처리가 결과를 크게 좌우합니다.

5

팔 두 개: 14차원과 서로 비켜 주기

두 팔을 함께 움직이는 가장 정직한 방법은 두 팔의 관절각을 이어 붙여 14차원 점 하나로 보는 것입니다. 충돌 검사에 왼팔-오른팔 검사가 들어가니, 이 공간의 자유 영역은 ‘두 팔이 동시에 그 자세일 때 아무것도 안 부딪히는 조합’이에요. 플래너 코드는 4장과 똑같고 벡터 길이만 14입니다.

더 쉬워 보이는 방법은 한 팔씩 차례로 계획하는 것입니다. 왼팔을 먼저 옮기는 동안 오른팔은 출발 자세로 가만히 있는 장애물로 보고, 왼팔이 도착하면 그 자세를 장애물로 놓고 오른팔을 계획해요. 각각은 7차원이라 빠르지만, 이 방식은 완전하지 않습니다. 두 팔이 서로 길을 내줘야만 풀리는 문제에서는, 한쪽이 가만히 서 있는 동안 다른 쪽이 갈 길이 아예 없을 수 있어요.

찾은 경로는 다듬은 뒤 시간을 붙여야 실행할 수 있습니다. 여기서는 구간마다 ‘가장 많이 움직이는 관절이 최대 속도의 절반으로 움직이는 시간’을 배정하고, 구간 안에서는 부드럽게 가속·감속하게 했어요. 실제 시스템은 가속도 한계까지 넣은 시간 최적화(예: TOPP-RA)를 씁니다.

핵심두 팔을 한 점으로
  1. 두 팔의 관절각 14개를 한 줄로 묶은 점. 플래너는 이 점 하나를 움직입니다.
  2. 책상, 장애물, 그리고 팔끼리까지 모두 안 부딪혀야 자유. 팔끼리 검사 때문에 두 팔을 따로 풀 수 없어요.
  3. 경로의 구간마다 가장 많이 움직이는 관절이 최대 속도의 절반으로 움직이게 시간을 붙입니다.
한 팔씩          ① qL: 출발 → 목표      (qR = 출발 자세로 고정)
                 ② qR: 출발 → 목표      (qL = 목표 자세로 고정)
                 빠르지만, 서로 비켜 줘야 하는 문제는 못 푼다

다듬기          경로 위 두 점 i < j를 뽑아
                 직선 i→j가 자유면 그 사이 점들을 지운다  (200번 반복)

시간 붙이기     Δt구간 = maxk |Δqk| / (0.5 · vmax,k)

def shortcut(path, free, iters=200):
    for _ in range(iters):
        i, j = sorted(np.random.choice(len(path), 2, replace=False))
        if j - i > 1 and edge_free(path[i], path[j], free):
            path = path[:i+1] + path[j:]
    return path

행렬로 보기14차원 공간의 점은 숫자 14개의 한 줄

14차원은 그릴 수 없지만, 계산은 2차원과 똑같습니다. 점은 숫자 한 줄, 거리는 칸별 차이의 제곱합, 직선은 칸별로 같은 비율 섞기예요. RRT와 RRT-Connect가 하는 계산은 이 세 가지가 전부라서, 차원이 늘어도 코드는 그대로이고 계산량과 공간의 넓이만 늘어납니다.

정리

  1. 순기구학은 변환을 차례로 곱하는 것이다. 관절각 7개를 손 자세로 바꾸는 함수이고, 플래너는 이 함수를 수만 번 부른다.
  2. 충돌 검사는 C-space 장애물 안인지 묻는 예/아니오 질문이다. 고차원에서는 장애물을 미리 그릴 수 없으니 필요할 때마다 팔을 놓아 보고, 빠르게 하려고 구로 근사한다.
  3. IK는 오차를 줄이는 한 걸음의 반복이다. 답이 여럿일 수 있고, 7관절 팔의 남는 자유도는 손을 그대로 둔 채 팔 모양을 바꾸는 데 쓴다.
  4. RRT는 차원과 상관없이 같은 코드다. 차원이 높아지면 양쪽에서 자라는 RRT-Connect와 다듬기 같은 후처리가 중요해진다.
  5. 두 팔은 하나의 14차원 점으로 볼 때 서로 비켜 줄 수 있다. 나눠서 계획하면 빠르지만 풀 수 있는 문제를 놓친다.
실제로 쓰는 도구ROS 2의 MoveIt 2가 OMPL 라이브러리의 RRT-Connect 등 여러 플래너와 충돌 검사, 시간 최적화를 묶어 줍니다. GPU를 쓰는 cuRobo는 이 페이지처럼 구로 감싼 팔을 수천 개 자세로 한꺼번에 검사해요.
우리 가사 로봇으로바퀴 달린 몸통에 7자유도 팔 두 개면, 몸통 위치까지 합쳐 17차원입니다. 접시를 집는 동안 몸통은 세워 두고 팔만 계획하는 식으로 차원을 나누는 게 흔한 출발점이에요.
LLM과 학습 정책 사이에서LLM이 ‘접시를 들어 선반 아래 칸에’를 정하면, IK가 손 목표를 관절 목표로 바꾸고 플래너가 그 사이 길을 찾습니다. 문 손잡이처럼 접촉이 많은 동작은 RL이나 모방학습 정책이 맡고요.

2관절 RRT 실습에서 C-space 그림으로 본 모든 것, 장애물의 모양, 트리가 자라는 방식, 다듬기가 여기서도 그대로 일어나고 있습니다. 다만 우리 눈에 보이지 않을 뿐이에요. 직접 만든 MuJoCo 시뮬레이터에서는 충돌 검사를 MuJoCo에 맡기고(mj_forward 뒤 접촉 목록 확인) 이 페이지의 RRT-Connect 코드를 그대로 얹어 볼 수 있습니다.
