사실로 적고, 탐색으로 찾고, 트리로 실행한다

지금까지는 어떻게 움직일지를 풀었어요. 경로를 찾고, 팔 관절 경로를 RRT로 짜고, 물체를 옮겼죠. 이번 주제는 무엇을 어떤 순서로 할지입니다. “식탁 위 접시를 식기세척기에 넣어 줘”를 실행하려면 로봇은 문을 언제 열지, 어느 손으로 무엇을 들지부터 정해야 해요.

1부에서는 세상을 참·거짓 사실의 집합으로 적는 STRIPS, 그 위의 상태 공간 탐색과 휴리스틱, 표준 언어 PDDL을 다룹니다. 2부에서는 실행 중의 실패를 받아내는 행동 트리와, 말로 받은 명령을 LLM으로 계획하고 검증하는 방법을 봐요.

1부

계획: 사실의 집합 위에서 탐색한다

로봇팔 단원의 RRT는 연속 공간에서 길을 찾았습니다. 작업 계획은 이산 공간에서 찾아요. 상태는 ‘지금 참인 사실의 집합’이고, 행동은 그 집합을 바꾸는 규칙입니다. 자료구조 시간에 배운 BFS와 우선순위 큐가 그대로 쓰여요.

1

세상을 참·거짓 사실로 적는다

부엌을 로봇이 계획할 수 있는 모양으로 적어 봅시다. 좌표나 관절각은 모두 빼고, 순서를 정하는 데 필요한 것만 사실(fact)로 남겨요. at(table)은 “로봇이 식탁 앞에 있다”, on(p1, table)은 “접시 1이 식탁 위에 있다”, holding(L, p1)은 “왼손이 접시 1을 들고 있다”입니다. 가능한 사실 전체를 F라 하고, 지금 참인 사실들의 집합 s를 상태라고 불러요.

행동은 세 목록으로 정의합니다. 실행 전에 참이어야 하는 전제조건 pre, 실행 뒤 거짓이 되는 삭제 목록 del, 새로 참이 되는 추가 목록 add. 1971년 스탠퍼드의 이동 로봇 셰이키(Shakey)를 위해 만든 이 표현을 STRIPS라고 해요. 예를 들어 pick(p1, table, L)은 at(table), on(p1, table), free(L)이 필요하고, on(p1, table)과 free(L)을 지우고, holding(L, p1)을 추가합니다.

집합 연산이 곧 비트 연산이라는 점도 기억해 두세요. 사실마다 비트 하나를 주면 상태는 정수 하나가 되고, 전제조건 검사는 AND, 상태 전이는 AND NOT과 OR 한 번이면 끝나요. 아래 실습의 사실 칸 하나하나가 그 비트입니다.

행동 하나 = 전제조건, 삭제, 추가
(1)
  1. 1실행할 수 있는 조건. 필요한 사실이 모두 지금 상태 s에 들어 있어야 해요. 하나라도 빠지면 그 행동은 아예 후보가 아닙니다.
  2. 2삭제 목록. 행동 뒤에 거짓이 되는 사실. pick이라면 on(p1, table)과 free(L)이에요.
  3. 3추가 목록. 새로 참이 되는 사실. pick이라면 holding(L, p1). 목록에 없는 사실은 그대로 둡니다. “나머지는 안 변한다”를 따로 적지 않아도 되는 게 STRIPS의 장점이에요.
계획 문제와 계획
(2)
  1. 1사실 전체 F. 접시가 n개면 5n + 6개예요. 위치 2, 접시 위치 2n, 빈손 2, 손에 든 것 2n, 세척기 안 n, 문 상태 2.
  2. 2행동 전체 A. 인자를 모두 채운 ‘접지된(ground)’ 행동이라, 접시 2개 부엌엔 26개가 있어요.
  3. 3처음 상태 s0. 로봇은 식탁 앞, 접시는 모두 식탁 위, 두 손은 비었고 세척기 문은 닫힘.
  4. 4목표 G. 모든 접시가 세척기 안에 있고 문이 닫혀 있다. 목표에 없는 사실, 예를 들어 로봇이 어디 있는지는 상관없어요.
  5. 5성공 조건. 계획 π를 차례로 적용한 마지막 상태가 G를 포함하면 끝. 같은 목표를 이루는 계획은 여럿이고, 보통은 가장 짧은 것을 찾습니다.
비트로 쓰면
(3)
  1. 1전제조건 검사. 상태와 pre를 AND 했을 때 pre가 그대로 남으면 실행할 수 있어요.
  2. 2전이. del의 비트를 끄고 add의 비트를 켭니다. 파이썬 frozenset이라면 (s - dele) | add예요.

    2

    상태 공간을 탐색한다

    상태가 집합이고 행동이 집합 사이의 화살표라면, 계획 문제는 그래프에서 최단 경로 찾기입니다. 노드는 상태, 간선은 행동, 출발은 s0, 도착은 G를 포함하는 아무 상태. 경로 계획 단원의 격자 탐색과 같은데, 이번 그래프는 지도에 미리 그려져 있지 않고 행동 규칙으로 그때그때 펼쳐져요.

    문제는 크기입니다. 접시가 하나 늘 때마다 도달 가능한 상태가 약 4배씩 늘어요. 그래서 휴리스틱 h(s), 즉 “목표까지 대략 몇 단계 남았나”를 추정해 유망한 상태부터 펼칩니다. h가 실제 남은 비용 h*를 절대 넘지 않으면(허용적) A*는 최단 계획을 보장해요.

    남은 목표 사실의 개수는 이 부엌에서 허용적이지만(행동 하나가 목표 사실을 하나까지만 만드니까) 너무 약합니다. 접시마다 load 한 번, 손에 없으면 pick 한 번, 문은 열고 닫기를 세면 훨씬 강하면서 여전히 허용적이에요. 범용 계획기는 영역 지식 없이 휴리스틱을 자동으로 만드는데, 핵심 아이디어는 삭제 완화입니다. del 목록을 무시하면 사실이 늘기만 해서 문제가 쉬워지고, 그 쉬운 문제의 비용을 h로 써요. FF나 Fast Downward 같은 실전 계획기가 이 계열입니다.

    상태 수는 지수적으로 는다
    (4)
    1. 1상한. 사실 |F|개가 각각 참이거나 거짓이니 최대 2|F|개. 접시 2개면 216 = 65,536이지만, 손 하나가 접시 둘을 드는 상태처럼 말이 안 되는 조합은 도달할 수 없어요.
    2. 2실제로 도달 가능한 수. 접시 1개 20, 2개 92, 3개 396, 4개 1,620, 5개 6,372. 거의 4배씩이라 접시 10개면 수백만 개입니다.
    A*: 지나온 비용 + 남은 비용 추정
    (5)

    2. 2h(s). s에서 목표까지 남은 행동 수의 추정. 우선순위 큐에서 f가 작은 상태부터 꺼내요.
    3. 3허용성. h가 진짜 남은 비용 h*를 넘지 않으면 A*가 처음 찾은 계획이 최단입니다. 넘을 수 있는 h를 쓰면 빨라질 수 있지만 보장은 사라져요.
    두 가지 허용적 휴리스틱
    (6)
    1. 1접시 항. 아직 세척기에 없는 접시마다 load가 한 번, 손에도 없으면 pick이 한 번 더 필요해요. [·]는 참이면 1, 거짓이면 0입니다.
    2. 2문 항. 남은 접시가 있을 때 문이 닫혀 있으면 열고 닫기 2번, 열려 있으면 닫기 1번.
    3. 3이동 항. 식탁에 접시가 남았는데 세척기 앞이면 다녀오기 2번, 그 밖에 세척기 앞이 아니면 1번. 서로 다른 종류의 행동만 세었으니 합해도 h*를 넘지 않아요.
    삭제 완화로 휴리스틱 자동으로 만들기
    (7)
    1. 1완화된 전이. del을 무시하면 한 번 참이 된 사실은 계속 참이에요. 손이 하나여도 접시를 몇 개든 ‘들 수’ 있는 세상입니다.
    2. 2사실 하나의 비용. 그 사실을 추가하는 행동 중 가장 싼 것. 행동의 비용은 전제조건 비용의 합에 1을 더한 값이에요. 고정점이 될 때까지 반복해 계산합니다.
    3. 3hadd. 목표 사실 비용의 합. 같은 행동을 중복해서 세니 허용적이 아니에요. 합 대신 최댓값을 쓰면 허용적인 hmax가 되지만 이 부엌에선 너무 약합니다.

    3

    PDDL과 파이썬으로

    지금까지의 규칙을 계획 분야의 표준 언어 PDDL로 적으면 아래와 같아요. 영역(domain) 파일엔 술어와 행동 틀을, 문제(problem) 파일엔 물체, 처음 상태, 목표를 적습니다. ?p, ?h 같은 변수가 있어서 접시가 100개여도 행동 정의는 그대로예요. 계획기가 변수에 물체를 채워 넣는 일을 접지(grounding)라고 하고, 실습 1의 행동 목록이 그 결과입니다.

    두 파일을 Fast Downward나 파이썬의 pyperplan 같은 계획기에 넘기면 계획이 나와요. 그래도 한 번은 직접 짜 보는 게 좋습니다. 상태를 frozenset으로 두면 BFS는 스무 줄 남짓이고, A*는 큐를 우선순위 큐로 바꾸고 h를 더하면 끝이에요.

    kitchen-domain.pddl · 영역
    (define (domain kitchen)
  (:requirements :strips :typing)
  (:types plate loc hand)
  (:constants table dw - loc)
  (:predicates (at ?l - loc) (on ?p - plate ?l - loc)
               (in ?p - plate) (holding ?h - hand ?p - plate)
               (free ?h - hand) (dw_open) (dw_closed))

  (:action move
    :parameters (?from ?to - loc)
    :precondition (at ?from)
    :effect (and (at ?to) (not (at ?from))))

  (:action pick
    :parameters (?p - plate ?l - loc ?h - hand)
    :precondition (and (at ?l) (on ?p ?l) (free ?h))
    :effect (and (holding ?h ?p)
                 (not (on ?p ?l)) (not (free ?h))))

  (:action put
    :parameters (?p - plate ?l - loc ?h - hand)
    :precondition (and (at ?l) (holding ?h ?p))
    :effect (and (on ?p ?l) (free ?h)
                 (not (holding ?h ?p))))

  (:action load
    :parameters (?p - plate ?h - hand)
    :precondition (and (at dw) (dw_open) (holding ?h ?p))
    :effect (and (in ?p) (free ?h) (not (holding ?h ?p))))

  (:action open_dw
    :parameters (?h - hand)
    :precondition (and (at dw) (dw_closed) (free ?h))
    :effect (and (dw_open) (not (dw_closed))))

  (:action close_dw
    :parameters (?h - hand)
    :precondition (and (at dw) (dw_open) (free ?h))
    :effect (and (dw_closed) (not (dw_open)))))

    planner.py · STRIPS와 BFS
    from collections import deque
from dataclasses import dataclass

@dataclass(frozen=True)
class Action:
    name: str
    pre: frozenset
    add: frozenset
    dele: frozenset          # del은 파이썬 예약어라 dele

def applicable(s, a):
    return a.pre <= s           # 식 (1): pre(a) ⊆ s

def apply(s, a):
    return (s - a.dele) | a.add  # (s \ del) ∪ add

def bfs(s0, goal, actions):
    frontier = deque([s0])
    parent = {s0: None}
    while frontier:
        s = frontier.popleft()
        if goal <= s:            # G ⊆ s
            return extract_plan(parent, s)
        for a in actions:
            if applicable(s, a):
                t = apply(s, a)
                if t not in parent:
                    parent[t] = (s, a)
                    frontier.append(t)
    return None

def extract_plan(parent, s):
    plan = []
    while parent[s] is not None:
        s, a = parent[s]
        plan.append(a.name)
    return plan[::-1]
    
      
    planner.py · A*와 직접 설계한 h
    import heapq

def astar(s0, goal, actions, h):
    tie = 0                      # f가 같을 때 비교용
    openq = [(h(s0), 0, tie, s0)]
    g = {s0: 0}
    parent = {s0: None}
    while openq:
        f, gs, _, s = heapq.heappop(openq)
        if gs > g[s]:
            continue             # 더 짧은 길이 이미 있음
        if goal <= s:
            return extract_plan(parent, s)
        for a in actions:
            if a.pre <= s:
                t = (s - a.dele) | a.add
                if t not in g or gs + 1 < g[t]:
                    g[t] = gs + 1
                    parent[t] = (s, a)
                    tie += 1
                    heapq.heappush(openq, (gs + 1 + h(t), gs + 1, tie, t))
    return None

def h_design(s, plates):         # 식 (6)
    left = [p for p in plates if f"in({p})" not in s]
    if not left:
        return 0 if "dw_closed" in s else 1
    h = sum(1 + (f"holding(L, {p})" not in s
                 and f"holding(R, {p})" not in s) for p in left)
    h += 2 if "dw_closed" in s else 1
    on_table = any(f"on({p}, table)" in s for p in left)
    if on_table and "at(dw)" in s:
        h += 2
    elif on_table or "at(dw)" not in s:
        h += 1
    return h

    넘어지면 다시: 행동 트리
    
  
    
    
    계획을 순서대로 실행하다 한 단계가 실패하면 어떻게 할까요? 처음부터 다시 계획할 수도 있지만, 흔한 실패는 미리 대비해 두는 편이 빠릅니다. 게임 AI에서 시작해 지금은 ROS 2 내비게이션 스택(Nav2)의 기본 구조가 된 행동 트리(behavior tree)가 그 방법이에요.
    
    
    트리는 일정 주기로 틱(tick)을 받습니다. 틱은 루트에서 출발해 아래로 내려가고, 노드는 성공(S), 실패(F), 진행 중(R) 중 하나를 돌려줘요. 잎에는 상태를 확인하는 조건 ◇과 로봇을 움직이는 행동 !이 있고, 안쪽 노드는 사실상 둘입니다. 시퀀스 →는 자식이 하나라도 실패하면 실패하는 AND, 폴백 ?는 자식이 하나라도 성공하면 성공하는 OR이에요.
    
    
    핵심은 매 틱 루트부터 다시 확인한다는 점입니다. “택배를 들고 있나?”를 매번 묻기 때문에, 가는 길에 떨어뜨려도 따로 코드를 짜지 않았는데 트리가 알아서 다시 집으러 가요. 폴백의 첫 자식에 “이미 됐나?” 조건을 두는 이 패턴 덕분에, 실패가 어디서 나든 트리는 그 자리에서 이어서 합니다.

    bt.py · 행동 트리의 뼈대 (py_trees도 같은 구조)
    SUCCESS, FAILURE, RUNNING = "S", "F", "R"

class Sequence:                       # →  AND
    def __init__(self, *kids): self.kids = kids
    def tick(self, bb):
        for k in self.kids:
            st = k.tick(bb)
            if st != SUCCESS:
                return st             # F나 R이면 여기서 멈춤
        return SUCCESS

class Fallback:                       # ?  OR
    def __init__(self, *kids): self.kids = kids
    def tick(self, bb):
        for k in self.kids:
            st = k.tick(bb)
            if st != FAILURE:
                return st             # S나 R이면 여기서 멈춤
        return FAILURE

class Condition:                      # ◇
    def __init__(self, fn): self.fn = fn
    def tick(self, bb):
        return SUCCESS if self.fn(bb) else FAILURE

class Retry:                          # ↻
    def __init__(self, kid, n): self.kid, self.n, self.fails = kid, n, 0
    def tick(self, bb):
        st = self.kid.tick(bb)
        if st == FAILURE:
            self.fails += 1
            return FAILURE if self.fails >= self.n else RUNNING
        if st == SUCCESS:
            self.fails = 0
        return st

tree = Fallback(
    Condition(lambda bb: bb.pkg_at_drop),
    Sequence(
        Fallback(Condition(lambda bb: bb.holding),
                 Sequence(Fallback(Condition(lambda bb: bb.near_pkg),
                                   Sequence(Fallback(Condition(lambda bb: bb.door_open),
                                                     OpenDoor(), AskHuman()),
                                            GoToPackage())),
                          Retry(PickWithBothArms(), 3))),
        Fallback(Condition(lambda bb: bb.at_living), GoToLiving()),
        PlaceAtDrop()))

while tree.tick(robot.blackboard) != SUCCESS:   # 5 Hz로 틱
    robot.sleep(0.2)

    말로 받은 명령: LLM 계획기와 검증
    
  
    
    
    최종 프로젝트의 로봇은 “식탁 좀 치워 줘” 같은 말을 듣습니다. 이 말을 목표로 바꾸고 계획을 세우는 데 LLM을 쓰는 방법은 크게 셋이에요.

    LLM은 번역, 계획은 계획기말을 PDDL 목표로 옮기는 일만 LLM에 맡기고, 탐색은 1부의 계획기가 합니다(LLM+P, 2023). 계획의 정확성은 보장되지만 영역 파일이 있어야 해요.

    llm_plan.py · 제안과 검증 루프
    SKILLS = """너는 가사 로봇의 계획기다. 한 줄에 스킬 하나만 쓴다.
move(from, to)       # 장소: table, dw
pick(p, loc, hand)   # hand: L, R. 빈손이어야 한다
put(p, loc, hand)
load(p, hand)        # 식기세척기 앞, 문이 열려 있어야 한다
open_dw(hand)        # 빈손 필요
close_dw(hand)       # 빈손 필요"""

def plan_with_llm(command, s0, goal, actions, rounds=4):
    prompt = f"{SKILLS}\n현재 상태: {sorted(s0)}\n명령: {command}\n계획:\n"
    for r in range(rounds):
        text = llm(prompt)                    # 아무 LLM API
        ok, err = validate(text, s0, goal, actions)
        if ok:
            return text, r + 1
        prompt += f"{text}\n검증 실패: {err}\n고친 전체 계획:\n"
    return None, rounds

def validate(text, s0, goal, actions):
    s = frozenset(s0)
    by_name = {a.name: a for a in actions}
    for i, line in enumerate(text.splitlines(), 1):
        line = line.split("#")[0].strip()
        if not line:
            continue
        a = by_name.get(line)
        if a is None:
            return False, f"{i}행 '{line}': 없는 스킬이거나 인자가 틀림"
        missing = a.pre - s
        if missing:
            return False, f"{i}행 {line}: 전제조건 {sorted(missing)}가 거짓"
        s = (s - a.dele) | a.add
    if not goal <= s:
        return False, f"끝났지만 목표 {sorted(goal - s)}가 아직 거짓"
    return True, None
