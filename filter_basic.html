방금 한 일은 지금까지 본 것과 맞지 않는 칸을 지우는 것이었어요. 그런데 진짜 로봇은 이렇게 깔끔하지 않아요. 바퀴가 미끄러져 한 칸 명령에 두 칸을 가기도 하고, 센서가 벽을 문으로 잘못 보기도 하죠. 그러면 어떤 칸을 '후보다, 아니다'로 딱 자를 수가 없어요.

1믿음: 위치를 확률로 적기

로봇의 믿음(belief)은 복도 칸마다 붙인 확률이에요. 막대가 높은 칸일수록 "여기 있을 것 같다"는 뜻이죠. 로봇은 어느 한 칸에는 반드시 있으니, 모든 칸의 확률을 더하면 항상 1(100%)이 됩니다.

확률이 낯설면 이렇게 생각해 보세요. 상상 속 로봇 100대를 칸마다 나눠 세워 둡니다. 어떤 칸에 30대가 서 있으면 그 칸의 믿음은 0.3이에요. 이 상상은 나중에 파티클 필터에서 그대로 진짜 알고리즘이 됩니다.

믿음 그려 보기

위 줄에 아무 크기로 점수를 그려 보세요. 아래 줄은 그 점수를 점수 합계로 나눈 확률이에요. 어떻게 그려도 아래 막대의 합은 1이 됩니다.

점수 합계 36.00확률 합계 1.00가장 그럴듯한 칸 -
\[ \class{qbel}{\mathrm{bel}(x_t)} = P\big(\,x_t \mid \class{qsensor}{z_{1:t}},\ \class{qmotion}{u_{1:t}}\,\big), \qquad \sum_{x} \mathrm{bel}(x) = 1 \]

설명 칸에 마우스를 올리거나 눌러 보세요. 식에서 해당 부분만 진하게 보여요.

믿음은 "지금까지 보고 움직인 것을 다 고려하면, 나는 어디에 있을 것 같은가"를 칸마다 적어 둔 표예요. 합은 언제나 1.

2센서: 보고 나서 믿음 고치기

처음엔 아무것도 모르니 모든 칸이 똑같이 1/36이에요. 이때 로봇이 "앞에 문이 보인다"고 했어요. 상식적으로 문 앞 칸은 더 그럴듯해지고, 벽 앞 칸은 덜 그럴듯해지겠죠. 그런데 얼마나일까요? 센서는 가끔 틀리는데요.

공식부터 외우지 말고, 상상 속 로봇 100대로 직접 세어 봅시다.

로봇 100대로 세어 보기

세 단계를 차례로 눌러 보세요. 아래 슬라이더로 센서의 정확도를 바꾸면 숫자가 따라 바뀌어요.

문 앞에 선 로봇 벽 앞에 선 로봇 '문'이라고 맞게 답함 '문'이라고 잘못 답함

방금 한 계산이 바로 베이즈 정리예요. "문 앞에 있으면서 '문'이라고 답한 로봇 수"를 "어디서든 '문'이라고 답한 로봇 수"로 나눈 것이죠. 식으로 쓰면 이렇습니다.

\[ P(x \mid z) = \frac{P(z \mid x)\,P(x)}{P(z)} \]
\[ \class{qbel}{\mathrm{bel}(x)} = \class{qnorm}{\eta}\;\, \class{qsensor}{p(z \mid x)}\;\, \class{qpred}{\overline{\mathrm{bel}}(x)} \]

뜻으로 읽으면 한 줄이에요. 새 믿음은 '원래 믿음 × 센서가 그 칸을 지지하는 정도'를, 합이 1이 되게 다시 맞춘 것. 곱하고, 다시 1로 맞춘다. 이게 전부예요. 100대 실험에서 '문'이라 답하지 않은 로봇을 흐리게 지운 게 곱하기, 남은 로봇 수로 나눈 게 다시 1로 맞추기였어요.

곱하고, 다시 1로 맞추기

관측 버튼을 눌러 보세요. 막대를 누르면 그 칸의 계산이 아래 표에 나와요. 버튼을 여러 번 누르면 새 믿음이 다음 차례의 원래 믿음이 됩니다.

센서가 틀려도 괜찮을까? 한 번 틀린 관측은 막대를 조금 흔들 뿐이에요. '문이 보였다'를 세 번 누르고 중간에 '벽이 보였다'를 한 번 섞어 보세요. 관측이 쌓이면 맞는 쪽이 이깁니다.
조심할 것 하나. 곱하기라서 \(p(z \mid x) = 0\)인 칸은 한 번에 0이 되고, 그 뒤로 무엇을 곱해도 영영 0이에요. '잘못 볼 확률'을 0으로 내리고 '문이 보였다'를 눌러 보세요. 벽 앞 칸이 전부 사라집니다. 센서 모델에는 0을 넣지 않는 게 안전해요.

센서는 곱하기다. 관측과 맞는 칸은 커지고, 안 맞는 칸은 작아진다. 그리고 합이 1이 되게 다시 맞춘다.

3이동: 움직이면 흐려진다

이번엔 로봇에게 "한 칸 앞으로"라고 명령했어요. 로봇이 움직였으니 믿음도 통째로 한 칸 오른쪽으로 옮겨 가야겠죠. 그런데 바퀴가 미끄러져 제자리(0칸)에 있거나 두 칸을 갈 수도 있어요. 그래서 막대가 옆으로 번집니다.

눈을 감고 걸어 본 적 있나요? 몇 걸음만 가도 내가 어디쯤인지 점점 자신이 없어지죠. 보지 않고 움직이기만 하면 믿음은 계속 흐려져요.

확률 흘려보내기

'한 칸 이동'을 눌러 보세요. 아랫줄 막대를 누르면 그 칸으로 어디에서 얼마나 흘러왔는지 화살표로 보여요. 화살표가 굵을수록 많이 흘러온 거예요.

"한 칸 앞으로"를 받았을 때 실제로 가는 거리
가장 높은 막대 (확신도) 100%이동 횟수 0번
\[ \class{qpred}{\overline{\mathrm{bel}}(x_t)} = \class{qsum}{\sum_{x_{t-1}}}\; \class{qmotion}{p(x_t \mid u_t,\, x_{t-1})}\;\, \class{qbel}{\mathrm{bel}(x_{t-1})} \]
컴퓨터공학의 눈으로 보면 이 계산은 1차원 컨볼루션이에요. 사진에 흐림(blur) 필터를 거는 것과 같은 연산이죠. 모션 모델이 흐림 필터의 커널 역할을 합니다. 미끄러질 확률을 0으로 하면 커널이 [0, 1, 0]이 되어 그냥 한 칸 밀기만 해요.

움직임은 흘려보내기다. 믿음을 명령만큼 옮기고, 불확실한 만큼 번지게 한다. 확률의 합은 그대로 1.

4베이즈 필터: 두 박자의 반복

이제 재료가 다 모였어요. 로봇의 일생은 두 박자의 반복입니다. 움직이면 흐려지고(예측), 보면 뾰족해진다(갱신). 이 반복을 베이즈 필터라고 해요. 지금처럼 공간을 칸으로 나눠 계산하는 버전은 히스토그램 필터라고도 부릅니다.

\[ \class{qpred}{\overline{\mathrm{bel}}(x_t)} = \sum_{x_{t-1}} \class{qmotion}{p(x_t \mid u_t,\, x_{t-1})}\;\, \mathrm{bel}(x_{t-1}) \]
\[ \class{qbel}{\mathrm{bel}(x_t)} = \class{qnorm}{\eta}\;\, \class{qsensor}{p(z_t \mid x_t)}\;\, \overline{\mathrm{bel}}(x_t) \]

히스토그램 필터 돌려 보기

'이동'과 '관측'을 번갈아 누르거나 자동 재생을 켜세요. 파란 막대가 지금 믿음, 점선이 직전 단계의 믿음이에요. 진짜 로봇은 실제로 미끄러지고, 센서도 실제로 가끔 틀려요.

예측: 움직이면 흐려진다갱신: 보면 뾰족해진다

파이썬으로 쓰면 이게 전부예요. 위 실험에서 버튼을 누르면 지금 실행된 부분이 밝게 표시돼요.

import numpy as np

N = 36                                     # 복도 칸 수 (끝과 처음이 이어짐)
is_door = np.zeros(N, dtype=bool)
is_door[[2, 3, 8, 9, 19, 20, 27, 28]] = True

def predict(bel, slip):
    # 예측: 모든 출발 칸에서 확률을 흘려보낸다
    motion = {0: slip / 2, 1: 1 - slip, 2: slip / 2}   # 실제 이동 칸 수: 확률
    new = np.zeros(N)
    for x_prev in range(N):
        for step, p in motion.items():
            new[(x_prev + step) % N] += p * bel[x_prev]
    return new

def update(bel, saw_door, p_hit=0.85, p_false=0.10):
    # 갱신: 센서 모델을 곱하고, 합이 1이 되게 나눈다
    p_door = np.where(is_door, p_hit, p_false)          # 칸마다 '문'이라고 볼 확률
    likelihood = p_door if saw_door else 1 - p_door
    new = likelihood * bel
    return new / new.sum()                              # η 곱하기

bel = np.ones(N) / N                       # 처음엔 전혀 모름
for saw_door in [True, False, False, True]:
    bel = predict(bel, slip=0.2)
    bel = update(bel, saw_door)
print(bel.argmax(), bel.max())

베이즈 필터 = 예측(모션 모델로 흘려보내기) + 갱신(센서 모델로 곱하고 정규화). 위치 추정의 핵심은 이 두 줄이에요.

5격자의 한계: 칸이 너무 많아진다

복도는 36칸이면 충분했어요. 그런데 최종 프로젝트의 가사 로봇은 집 안 바닥의 x, y 위치에 더해 어느 쪽을 보고 있는지(θ)까지 알아야 해요. 칸 수는 차원이 하나 늘 때마다 곱해집니다. 직접 늘려 보세요.

칸 수 계산기

칸 하나를 갱신하는 데 계산이 100번쯤 들고(센서 빔 거리 계산 포함), 컴퓨터가 1초에 10억 번 계산한다고 쳐요. 로봇은 1초에 10번 이상 믿음을 갱신해야 쓸 만해요.

메모리 (칸마다 8바이트) 믿음 한 번 갱신
0.001초 0.1초 1분 하루 1년 1000년

더 아까운 점. 로봇이 거실에 있는 게 거의 확실해져도, 격자는 욕실 구석과 침대 밑 칸까지 매번 계산해요. 대부분의 칸은 확률이 0에 가까운데도요. 확률이 있는 곳에만 계산을 몰아줄 수는 없을까요?

격자는 정확하지만, 차원이 늘면 칸 수가 거듭제곱으로 폭발한다. 게다가 대부분의 칸은 거의 0이라 계산이 낭비된다.

6점으로 확률 그리기

선거 여론조사는 유권자 수천만 명에게 다 묻지 않아요. 천 명 정도만 무작위로 골라 물어도 전체 비율을 꽤 정확히 맞히죠. 확률분포도 마찬가지예요. 분포를 따라 점을 많이 뽑으면, 점이 빽빽한 곳이 확률이 높은 곳이 됩니다.

이 점 하나하나를 파티클(particle)이라고 불러요. 1장에서 말한 '상상 속 로봇 한 대'가 바로 파티클이에요. 칸마다 확률을 적는 대신, 상상 로봇들이 어디에 몰려 서 있는지로 믿음을 나타내는 거죠.

점 뽑기

검은 곡선이 진짜 분포, 맨 아래 점들이 뽑은 파티클, 파란 막대는 점을 구간별로 센 결과예요. 점 개수를 바꿔 보세요.

막대와 곡선이 어긋난 정도 -
점이 적으면 막대가 들쭉날쭉하지만, 많아질수록 곡선에 붙어요. 대략 점을 4배로 늘리면 어긋남이 절반으로 줄어요. 그리고 점은 저절로 확률이 높은 곳에 모이니, 계산도 그곳에 몰립니다. 5장의 고민이 이렇게 풀려요.

확률분포를 '점들의 무리'로 나타낼 수 있다. 점이 많은 곳이 확률이 높은 곳이다.

7파티클 필터: 상상 로봇들의 세 박자

베이즈 필터의 두 박자를 점으로 그대로 옮기면 파티클 필터가 됩니다. 갱신 박자가 '무게 달기'와 '다시 뽑기' 두 단계로 나뉘어서 세 박자예요.

① 이동하기 (예측)

\[ \class{qmotion}{x_t^{[i]} \sim p\big(x_t \mid u_t,\, x_{t-1}^{[i]}\big)} \]

상상 로봇 \(i\)번을 명령대로 움직이되, 각자 주사위를 굴려 조금씩 다르게. 미끄러짐을 흉내 내는 거예요.

② 무게 달기 (갱신의 곱하기)

\[ \class{qsensor}{w^{[i]} = p\big(z_t \mid x_t^{[i]}\big)} \]

진짜 로봇이 본 것을 그 상상 로봇 자리에서도 볼 법하면 무겁게, 아니면 가볍게.

③ 다시 뽑기 (갱신의 정규화)

\[ \class{qnorm}{\Pr(\text{pick } i) = \frac{w^{[i]}}{\sum_j w^{[j]}}} \]

무게에 비례하는 확률로 \(N\)대를 새로 뽑아요. 무거운 로봇은 여러 대로 복제되고, 가벼운 로봇은 사라져요. 일종의 자연선택이죠.

파티클 필터 한 박자씩

가운데 점들이 상상 로봇이에요. 무게를 달면 점 크기가 무게만큼 커져요. 아래 막대는 점으로 센 믿음, 검은 선은 4장의 정확한 베이즈 필터 결과예요. 둘이 거의 겹치는지 보세요.

할 일베이즈 필터 (칸)파티클 필터 (점)
예측모든 칸에서 모션 모델로 확률을 흘려보낸다 (Σ)점마다 주사위를 굴려 움직인다
곱하기칸마다 \(p(z \mid x)\)를 곱한다점마다 무게 \(w = p(z \mid x)\)를 단다
정규화합으로 나눠 1로 맞춘다 (\(\eta\))무게를 합으로 나누고, 무게대로 다시 뽑는다

파이썬으로 쓰면 이래요. 4장 코드의 is_door를 그대로 씁니다. 위 실험을 한 박자씩 진행하면 해당 줄이 밝게 표시돼요.

import numpy as np
rng = np.random.default_rng()

def door_at(x):
    return is_door[np.floor(x).astype(int) % N]

def particle_filter(xs, u, saw_door, sigma=0.25, err=0.12):
    n = len(xs)
    # ① 이동: 각자 주사위를 굴려 조금씩 다르게 움직인다
    xs = (xs + u + rng.normal(0, sigma, n)) % N
    # ② 무게: 관측과 맞을 법한 로봇일수록 무겁게
    p_door = np.where(door_at(xs), 1 - err, err)
    w = p_door if saw_door else 1 - p_door
    w = w / w.sum()
    # ③ 다시 뽑기: 같은 간격 빗살 n개로 무게 띠를 훑는다
    comb = (rng.random() + np.arange(n)) / n
    idx = np.searchsorted(np.cumsum(w), comb)
    return xs[np.minimum(idx, n - 1)]

xs = rng.uniform(0, N, size=150)           # 처음엔 복도 전체에 고르게
for saw_door in [True, False, False, True]:
    xs = particle_filter(xs, u=1, saw_door=saw_door)
다시 뽑기의 그림자. 다시 뽑을 때마다 복제가 생기니, 서로 다른 위치의 수는 줄어들어요. 운이 나쁘면 진짜 위치 근처에 상상 로봇이 한 대도 안 남는데, 그러면 아무리 관측해도 돌아오지 못해요. 이걸 파티클 고갈이라고 해요. 상상 로봇을 20대로 줄이고 로봇을 납치해 보세요. 검은 선(정확한 베이즈 필터)은 따라가는데 점들은 못 따라가는 장면이 보일 거예요. 해결책은 8장에서 만납니다.

파티클 필터 = 상상 로봇들을 주사위 굴려 움직이고, 관측과 맞는 만큼 무게를 달고, 무게대로 다시 뽑기. 베이즈 필터를 점으로 흉내 낸 것이다.

8집 안에서: 가사 로봇의 위치 찾기

최종 프로젝트의 가사 로봇이 집 안 어딘가에서 전원을 켰어요. 로봇은 집 지도는 갖고 있지만, 지도 위 어디에 있는지는 몰라요. 센서는 8방향 거리 센서(라이다 빔 8개)로, 벽이나 가구까지 거리를 잽니다.

무게는 이렇게 달아요. 상상 로봇마다 "내가 거기 있다면 빔 8개가 각각 몇 m가 나와야 하지?"를 지도로 계산하고, 진짜로 잰 거리와 비교해요. 비슷할수록 무거워집니다. 알고리즘은 7장과 완전히 같아요. 무게 공식만 바뀌었어요.

\[ \class{qnorm}{w^{[i]}} = \prod_{k=1}^{8} \exp\!\left( -\frac{\big(\class{qsensor}{z_k} - \class{qbel}{\hat{z}_k^{[i]}}\big)^2}{2\,\class{qsum}{\sigma}^2} \right) \]

집 안 파티클 필터

파란 점이 상상 로봇, 빨간 원이 진짜 로봇, 초록 선이 센서 빔이에요. 자동 주행을 켜거나 버튼(또는 그림을 누른 뒤 키보드 화살표)으로 운전하세요.

해 볼 것
  1. 침실 1에서 깨어나 보세요. 두 침실은 거울처럼 닮아서, 점 무리가 두 침실에 하나씩 생겨요. 로봇이 거실로 나와야 하나로 정리돼요. 봉우리가 여러 개인 믿음을 자연스럽게 다루는 게 파티클 필터의 큰 장점이에요.
  2. 위치를 찾은 뒤 로봇을 납치해 보세요. 점들은 옛 자리를 계속 믿어요. 이제 '무작위 상상 로봇 섞기'를 켜 보세요. 일부 상상 로봇이 늘 아무 데나 다시 뿌려지니, 새 자리를 찾아낼 기회가 생겨요. 7장의 파티클 고갈을 푸는 가장 간단한 방법이에요.
  3. 상상 로봇을 100대로 줄이거나 센서 σ를 0.1 m로 깐깐하게 해 보세요. 엉뚱한 곳으로 모이는 일이 잦아져요. 왜 그럴까요?

센서가 복잡해져도 파티클 필터는 그대로다. "내가 거기 있다면 무엇이 보였을까"만 계산할 수 있으면 무게를 달 수 있다.
