오차를 보고, 힘을 정한다

PID 제어기는 질문 하나를 아주 빠르게, 계속 반복합니다. 목표와 지금 사이의 차이가 이만큼일 때, 모터에 얼마를 넣을까. 공장 설비의 대부분과 드론, 로봇 팔, 바퀴 로봇의 가장 안쪽 루프가 아직도 이 세 글자로 돌아가요.

오차를 세 번 다르게 봅니다. 지금 얼마나 틀렸나(P), 지금까지 쌓인 게 얼마나 되나(I), 얼마나 빨리 변하고 있나(D). 이 페이지는 레일 위의 카트로 세 항이 각각 무엇을 하는지 먼저 눈으로 확인하고, 바퀴 두 개짜리 TurtleBot과 Crazyflie 드론에서 P만으로 되는 문제, 안 되는 문제, 그리고 PID까지 가야 하는 문제를 차례로 풀어 봅니다.

1부

원리: 오차를 세 가지로 본다

로봇을 정하지 않고, 레일 위의 카트 하나로 시작합니다. 모터가 카트를 미는 힘 u를 정하는 게 제어기의 일이에요. 카트는 힘을 받으면 가속하고, 바닥 마찰이 조금 있고, 가끔 바람이 붑니다. 2부의 바퀴 로봇과 3부의 드론도 결국 이 카트와 같은 질문을 풉니다.

1

P는 용수철, D는 브레이크, I는 끈기

제어의 출발점은 오차 e = 목표 − 현재입니다. 가장 먼저 떠오르는 규칙은 “틀린 만큼 세게 밀자”, u = Kp·e예요. 이게 P 제어입니다. 물리적으로 보면 카트와 목표 사이에 용수철을 걸어 둔 것과 똑같아요. 멀리 있으면 세게 당기고, 가까워지면 약하게 당깁니다. 문제는 용수철에 매달린 물체가 늘 그렇듯, 목표를 지나쳐 앞뒤로 출렁인다는 거예요. 목표에 도착하는 순간 힘은 0이지만 속도는 아직 남아 있으니까요.

그래서 오차가 줄어드는 속도를 봅니다. 빠르게 다가오고 있으면 미리 반대로 밀어 브레이크를 거는 거죠. 이게 D 제어이고, 자동차의 쇼크업소버(댐퍼)와 같은 역할입니다. 오차 그래프에서 D는 지금 이 순간의 기울기예요.

마지막으로, 바람처럼 늘 같은 방향으로 미는 힘이 있으면 P와 D만으로는 목표에 닿지 못합니다. 용수철이 바람을 버티려면 늘어나 있어야, 즉 오차가 남아 있어야 하거든요. I 제어는 오차를 시간에 따라 계속 더해서, 작은 오차라도 오래 남아 있으면 미는 힘을 점점 키웁니다. 오차 그래프에서 I는 곡선 아래의 넓이예요.

파이썬
class PID:
    def __init__(self, kp, ki=0.0, kd=0.0):
        self.kp, self.ki, self.kd = kp, ki, kd
        self.integral = 0.0
        self.e_prev = None

    def update(self, ref, y, dt):
        e = ref - y                          # 오차
        self.integral += e * dt              # 넓이: 쌓인 오차
        de = 0.0 if self.e_prev is None else (e - self.e_prev) / dt
        self.e_prev = e                      # 기울기: 오차의 변화
        p = self.kp * e
        i = self.ki * self.integral
        d = self.kd * de
        return p + i + d                     # 세 몫의 합이 명령

pid = PID(kp=6.0, ki=3.0, kd=4.0)
x, v, dt = 0.0, 0.0, 0.002
for k in range(5000):                        # 10초
    u = pid.update(1.0, x, dt)               # 목표 1 m
    a = (u - 1.5 - 0.3 * v) / 1.0            # 바람 −1.5 N, 마찰
    v += a * dt
    x += v * dt

해 볼 것

  • [P]에서 레일을 눌러 목표를 옮겨 보세요. 용수철(파란 지그재그)이 카트를 당기고, 카트는 목표를 지나쳐 한참 출렁입니다. Kp를 키우면 빨리 가지만 더 많이 출렁여요.
  • [PD]로 바꾸면 청록 화살표가 나타납니다. 카트가 목표 쪽으로 빠르게 움직일 때 반대 방향을 가리켜요. 오차 그래프의 청록 접선이 가팔라질수록 화살표도 커집니다.
  • [PD]에서 [맞바람]을 켜 보세요. 카트가 목표에 못 미친 곳에 멈춥니다. 이때 용수철은 늘어난 채로 바람과 버티고 있어요. 남은 오차는 1.5 N ÷ Kp와 같습니다.
  • [PID]로 바꾸면 보라색 넓이가 쌓이면서 보라 화살표가 점점 커지고, 결국 카트를 목표까지 밀어 넣습니다. 다 도착한 뒤에도 보라 화살표는 남아 있어요. 바람을 대신 버텨 주는 몫입니다.
  • [PI]에서 Ki를 1.2보다 크게 올려 보세요. D 없이 I만 키우면 출렁임이 점점 커집니다. I는 과거를 보니 늘 한 박자 늦게 반응하거든요.

핵심

P는 지금의 오차(높이), I는 지금까지 쌓인 오차(넓이), D는 오차가 변하는 속도(기울기)를 봅니다. 명령은 이 세 몫의 단순한 합이에요. P가 주된 일을 하고, D는 지나치지 않게 미리 브레이크를 걸고, I는 끝까지 남는 작은 오차를 지웁니다.

2

게인 지도: 좋은 응답은 어디에 있나

게인 세 개를 고르는 걸 튜닝이라고 합니다. 목표를 0에서 1 m로 한 번에 바꾸고(계단 입력) 카트가 어떻게 따라가는지 보면, 응답의 품질을 숫자 몇 개로 잴 수 있어요. 목표의 90%에 처음 닿는 상승 시간, 목표를 얼마나 넘었는지의 오버슈트, 목표 ±2% 안에 들어와서 다시 나가지 않게 되는 정착 시간, 그리고 끝까지 남는 정상상태 오차입니다.

왼쪽 지도는 (Kp, Kd) 조합 1,200개를 전부 시뮬레이션해서 색으로 칠한 거예요. 지도에서 한 점을 고르면 오른쪽에 그 게인의 응답이 나옵니다. 점선 곡선은 출렁이지 않는 가장 빠른 감쇠, 임계 감쇠(ζ = 1)의 경계입니다. 곡선 아래쪽은 덜 감쇠되어 출렁이고, 위쪽은 너무 감쇠되어 굼뜹니다. 모터 힘은 ±20 N까지만 낼 수 있게 해 두었어요. 그래서 게인을 무한히 키워도 무한히 빨라지지는 않습니다.

  2. 2정착 시간. ±2% 안에 들어와서 다시 나가지 않는 시각. ζ < 1일 때의 근사예요.
파이썬
def step_metrics(t, x, ref=1.0, band=0.02):
    overshoot = max(0.0, x.max() - ref) / ref
    rise = t[np.argmax(x >= 0.9 * ref)]       # 처음 90%에 닿는 시각
    outside = np.abs(x - ref) > band * ref
    settle = t[np.nonzero(outside)[0][-1]] if outside.any() else 0.0
    ess = ref - x[-50:].mean()                # 마지막 구간의 평균 오차
    return overshoot, rise, settle, ess

best = None
for kp in np.linspace(0.5, 40, 40):           # 지도 = 격자 탐색
    for kd in np.linspace(0, 16, 30):
        t, x = simulate(kp, 0.0, kd)
        os_, tr, ts, ess = step_metrics(t, x)
        if os_ < 0.05 and (best is None or ts < best[0]):
            best = (ts, kp, kd)

  • [오버슈트] 지도로 바꿔 보세요. 점선 위쪽은 모두 0%입니다. 점선을 따라 오른쪽 위로 가면 정착 시간이 줄지만 줄어드는 폭은 점점 작아져요. ωn = √Kp라서 Kp를 4배로 키워야 2배 빨라집니다. 그 대신 아래 힘 그래프의 첫 순간이 커지고, Kp가 20을 넘으면 ±20 N 한계에 잘려요.
  • [맞바람]을 켜고 [정상상태 오차] 지도를 보세요. Kd와 상관없이 Kp에만 따라 오차가 줄어듭니다(세로 줄무늬). Ki를 3으로 올리면 가운데 영역의 오차가 지워지지만, 왼쪽(작은 Kp)은 I 때문에 출렁이고 오른쪽(큰 Kp)은 8초 안에 다 지우지 못해요. I가 남은 오차를 지우는 빠르기는 대략 Ki/Kp라서, P가 셀수록 I의 몫은 느리게 줄어듭니다.

핵심

Kp는 빠르기를, Kd는 출렁임을, Ki는 남는 오차를 맡습니다. 하지만 셋은 서로 얽혀 있어서 하나를 바꾸면 다른 지표도 움직여요. 그리고 모터의 힘에는 한계가 있으니 게인을 키우는 것만으로 무한히 좋아지지는 않습니다.

2부

바퀴 두 개: TurtleBot3

운동 모델 실습의 차동 구동 로봇입니다. 이 로봇에게 우리가 보내는 명령은 힘이 아니라 속도(v, ω)예요. 속도를 정하면 위치가 바로 따라오니, 카트보다 다루기 쉽습니다. 그래서 P만으로 되는 문제부터 시작해서, 같은 로봇이 PD와 PID를 필요로 하게 되는 순간을 찾아갑니다.

3

목표 지점까지: P만으로 충분할 때

로봇을 바닥의 한 점으로 보내려면 오차가 두 개 필요합니다. 목표까지의 거리 ρ와, 로봇이 바라보는 방향과 목표 방향 사이의 각도 α예요. 거리 오차로 전진 속도를, 각도 오차로 회전 속도를 정하면 됩니다. 둘 다 P 제어예요.

여기서는 P만으로 충분합니다. 우리가 정하는 게 속도이니, 오차가 줄어드는 빠르기가 곧 오차에 비례해요(ρ̇ = −Kρρ). 이런 시스템은 출렁일 관성이 없어서 지나치지 않고, 일정한 시간마다 오차가 절반씩 줄어드는 지수 감쇠를 합니다. 다만 두 가지는 조심해야 해요. 각도 오차는 −180°~180°로 감싸야(wrap) 하고, 목표가 뒤에 있으면 cos α가 음수가 되니 전진을 멈추고 먼저 돌아야 합니다.

그리고 제어기는 연속이 아니라 정해진 주기마다 계산합니다. 한 주기 동안은 같은 명령이 유지되니, Kα·Δt가 1을 넘으면 한 번에 목표 방향을 지나쳐 버려요. 2를 넘으면 지나치는 폭이 매번 커집니다. 관성이 없는 시스템도 P를 너무 키우면 떨리는 이유예요.

주의관성이 없는 시스템도 디지털 제어기는 정해진 주기마다 계산합니다. 게인 × 주기가 크면 떨려요.
파이썬
V_MAX, W_MAX = 0.22, 2.84            # TurtleBot3 Burger

def wrap(a):
    return (a + np.pi) % (2 * np.pi) - np.pi

def go_to_goal(pose, goal, k_rho=1.0, k_alpha=4.0):
    x, y, th = pose
    dx, dy = goal[0] - x, goal[1] - y
    rho = np.hypot(dx, dy)
    alpha = wrap(np.arctan2(dy, dx) - th)
    if rho < 0.01:
        return 0.0, 0.0                  # 도착
    v = min(k_rho * rho, V_MAX) * max(0.0, np.cos(alpha))
    w = np.clip(k_alpha * alpha, -W_MAX, W_MAX)
    return v, w                          # /cmd_vel 로 보낸다

rate = 10                                # Hz: 명령은 0.1초 동안 유지
for k in range(200):
    v, w = go_to_goal(pose, goal)
    pose = step_exact(pose, v, w, 1 / rate)

  • [10 Hz]에서 Kα를 18과 24로 올리고 목표를 로봇 옆쪽에 찍어 보세요. 18(KαΔt = 1.8)에서는 방향을 틀 때 좌우로 몇 번 떨다가 멈추고, 24(2.4)에서는 내내 떱니다. 같은 Kα로 [50 Hz]에 두면 다시 매끄러워져요.

핵심

속도를 직접 명령할 수 있는 몸에서는 P만으로 지나침 없이 목표에 갑니다. 출렁임은 ‘힘 → 속도 → 위치’처럼 적분이 두 번 끼어 있을 때 생기는데, 여기는 한 번뿐이니까요. 다만 디지털 제어기는 주기마다 계산하므로, 게인과 주기의 곱이 너무 크면 관성이 없어도 떨립니다.

4

선 따라가기: P에서 PID까지

이제 바닥에 그린 검은 선을 따라 일정한 속도 v로 달리는 로봇입니다. 아래에 붙은 적외선 센서가 선에서 옆으로 얼마나 벗어났는지, 횡방향 오차 e를 잽니다. 우리가 정하는 건 회전 속도 ω 하나예요.

목표 지점 문제와 달리 여기는 적분이 두 번 끼어 있습니다. ω를 주면 방향 θ가 바뀌고(1번), 방향이 기울어야 옆으로 움직여서 e가 바뀝니다(2번). 그래서 ω = Kp·e는 카트의 용수철과 같은 꼴이 되고, 로봇은 선을 중심으로 끝없이 S자를 그려요. 오차의 기울기, 즉 선에 다가가는 빠르기를 보는 D가 필요해집니다.

곡선 구간에서는 또 다른 일이 생깁니다. 반지름 R의 곡선을 따라가려면 늘 ω = v/R만큼 돌고 있어야 하는데, PD는 오차가 있어야만 ω를 냅니다. 그래서 곡선 내내 바깥쪽으로 일정한 오차가 남아요. 카트를 미는 바람과 똑같은 상황이고, I가 이걸 지웁니다. 한쪽 바퀴가 약할 때도 마찬가지예요.

선 따라가기의 운동
(11)

  2. 2ω를 주면 오차의 가속도가 바뀝니다. ω에서 e까지 적분이 두 번이에요.
P → PD → PID
(12)

  3. 3I항. 곡선에서 필요한 ω = v/R을 오차 없이 내 줍니다.

class LineFollower:
    def __init__(self, kp=8.0, ki=4.0, kd=10.0, rate=50):
        self.pid = PID(kp, ki, kd)
        self.dt = 1.0 / rate

    def command(self, e_lateral, v=0.2):
        # e > 0: 선이 로봇의 왼쪽에 있다 → 왼쪽(+ω)으로 돈다
        w = self.pid.update(0.0, -e_lateral, self.dt)
        return v, np.clip(w, -2.84, 2.84)

# 적외선 센서 배열 → 횡방향 오차
def line_error(readings, spacing=0.012):
    pos = np.arange(len(readings)) - (len(readings) - 1) / 2
    w = np.asarray(readings, float)       # 검은 선일수록 큰 값
    return spacing * (pos * w).sum() / w.sum()

5

바퀴 속도: 보이지 않는 안쪽 루프

3, 4장은 ‘바퀴 속도를 명령하면 그대로 나온다’고 가정했습니다. 실제로는 모터에 넣는 건 전압이고, 바퀴 속도는 마찰과 부하에 따라 달라져요. 그래서 로봇 펌웨어 안에는 엔코더로 바퀴 속도를 재서 전압을 고치는 속도 제어 루프가 바퀴마다 하나씩 돌고 있습니다. TurtleBot3의 Dynamixel 모터도 그래요.

DC 모터는 전압을 주면 속도가 1차 시스템으로 따라옵니다. P 제어로 V = Kp(ωref − ω)를 넣으면, 바퀴가 돌려면 전압이 필요하고 전압이 나오려면 오차가 있어야 하니 늘 목표보다 느리게 돕니다. 두 바퀴의 마찰이 조금만 달라도 두 바퀴가 서로 다르게 느려져요. 차동 구동에서 두 바퀴 속도의 차이는 곧 회전이니, 직진을 명령했는데 로봇이 휘어 갑니다.

I를 더한 PI 제어가 모터 속도 제어의 표준입니다. 여기선 D가 거의 필요 없어요. 모터는 1차 시스템이라 P만으로 지나치지 않고, 엔코더 속도 신호는 잡음이 커서 미분하기 나쁘거든요. 필요한 게 P와 I뿐이면 그것만 쓰면 됩니다.

class WheelPI:
    def __init__(self, kp=4.0, ki=30.0, v_max=12.0):
        self.kp, self.ki, self.v_max = kp, ki, v_max
        self.integral = 0.0

    def update(self, w_ref, w_meas, dt):
        e = w_ref - w_meas
        V = self.kp * e + self.ki * (self.integral + e * dt)
        if abs(V) < self.v_max:             # 포화 중엔 적분 멈춤
            self.integral += e * dt
        return np.clip(V, -self.v_max, self.v_max)

left, right = WheelPI(), WheelPI()
def on_cmd_vel(v, w, wl_meas, wr_meas, dt=0.01):
    wl_ref, wr_ref = twist_to_wheels(v, w)  # 운동 모델 실습의 역변환
    return (left.update(wl_ref, wl_meas, dt),
            right.update(wr_ref, wr_meas, dt))

  • [PI]로 바꾸면 두 바퀴가 1초 안에 목표에 붙고 로봇이 곧게 갑니다. 아래 그래프에서 왼쪽 바퀴의 전압이 오른쪽보다 높게 유지되는 걸 보세요. 뻑뻑한 만큼을 I가 더 넣고 있는 겁니다.
  • [피드포워드]를 켜면 ‘이 속도엔 대략 이 전압’을 미리 넣어 줍니다. 두 바퀴 모두 목표에 훨씬 가까워지는데도 로봇은 거의 똑같이 휘어요. 직진에 중요한 건 두 바퀴 속도의 차이이고, 그 차이를 만드는 왼쪽의 추가 마찰은 피드포워드가 모르니까요.

드론: Crazyflie를 3차원에서

드론은 바닥을 붙잡지 못하니 정할 수 있는 건 모터의 힘뿐입니다. 힘 → 가속도 → 속도 → 위치로 적분이 두 번이라 카트와 같은 꼴이고, 거기에 중력이 늘 아래로 당기고 바람이 옆에서 밉니다. 1부에서 본 세 항이 모두 필요한 몸이에요. 3D 화면은 끌어서 돌려 볼 수 있습니다.

드론 고도: 중력과 싸우는 P, PD, PID

고도만 보면 드론은 위쪽으로 미는 카트입니다. 다만 늘 mg로 끌어내리는 중력이 있어요. 1장의 맞바람과 같은 꼴인데 훨씬 셉니다. Crazyflie는 떠 있는 데만 최대 추력의 45%가 들어요.

그래서 드론 제어기는 거의 항상 중력 보상을 먼저 넣습니다. 떠 있는 데 필요한 m·g를 미리 더해 주고, PID는 그 위에서 ‘얼마나 더, 덜’만 정하게 하는 거예요. 이렇게 모델로 미리 계산해 넣는 걸 피드포워드라고 합니다. 오차를 보고 고치는 PID는 피드백이고요. 하지만 짐을 실어 무게가 바뀌면 피드포워드가 틀리고, 그 틀린 만큼을 I가 메웁니다.

  3. 3P항.
  4. 4I항. m̂이 실제 m과 다른 만큼(짐, 배터리 전압 저하)을 배웁니다.
  5. 5D항은 오차 대신 측정 속도 ż에 걸어요. 이유는 8장에서.

M_HAT, G, T_MAX = 0.027, 9.81, 0.58  # 제어기가 아는 질량

class AltitudePID:
    def __init__(self, kp=6.0, ki=3.0, kd=3.5, ff=True):
        self.pid = PID(kp, ki, 0.0)
        self.kd, self.ff = kd, ff

    def update(self, z_ref, z, vz, dt):
        a = self.pid.update(z_ref, z, dt) - self.kd * vz
        g = G if self.ff else 0.0
        T = M_HAT * (g + a)                 # 피드포워드 + 피드백
        return np.clip(T, 0.0, T_MAX)

드론 3D 위치: PID를 겹쳐 쌓기

쿼드로터의 추력은 늘 기체의 위쪽으로만 나옵니다. 옆으로 가려면 먼저 기울어야 해요. 그래서 3D 위치 제어는 PID를 두 겹으로 쌓습니다. 바깥 루프는 x, y, z 세 축에 PID를 하나씩 두고, 위치 오차로 원하는 가속도 ades를 계산해요. 그 가속도에 중력을 더한 벡터가 추력이 향해야 할 방향이니, 거기서 목표 기울기(롤, 피치)와 추력 크기가 나옵니다. 안쪽 루프는 그 기울기를 맞추도록 모터 네 개의 추력을 조절합니다.

이 구조는 안쪽 루프가 바깥보다 훨씬 빠를 때만 성립해요. 바깥 루프는 ‘기울기는 명령하면 금방 맞춰진다’고 믿고 계산하니까요. Crazyflie 펌웨어는 위치(100 Hz) → 자세 → 각속도(둘 다 500 Hz)의 세 겹이고, 여기서는 위치 100 Hz, 자세와 각속도 1 kHz로 돌립니다. 아래 슬라이더는 바깥 루프의 게인이에요. 세 축이 같은 게인을 씁니다.

바람은 서쪽에서 3 m/s로 붑니다. 기체가 바람을 버티려면 바람 쪽으로 계속 기울어 있어야 하고, 그러려면 PD는 오차가 필요해요. 6장의 짐과 같은 이야기를 이번엔 옆 방향으로 봅니다.

pos_pid = [PID(4.0, 1.5, 0.0) for _ in range(3)]   # x, y, z

def position_loop(p_ref, p, v, dt, kd=3.0):          # 100 Hz
    a = np.array([pos_pid[i].update(p_ref[i], p[i], dt) - kd * v[i]
                  for i in range(3)])
    f = M * (a + np.array([0, 0, G]))                # 원하는 힘 벡터
    pitch = np.arctan2(f[0], f[2])
    roll = np.arctan2(-f[1], np.hypot(f[0], f[2]))
    lim = np.radians(25)
    return np.clip(roll, -lim, lim), np.clip(pitch, -lim, lim), f[2]

def attitude_loop(ang_des, ang, rate, k_att=8.0, k_rate=60.0):  # 1 kHz
    rate_des = k_att * (ang_des - ang)
    return I_DIAG * k_rate * (rate_des - rate)       # 토크 (τx, τy, τz)

def step(state, p_ref, dt):
    roll_d, pitch_d, fz = position_loop(p_ref, state.p, state.v, dt)
    T = fz / (np.cos(state.roll) * np.cos(state.pitch))
    tau = attitude_loop(np.array([roll_d, pitch_d, 0.0]), state.ang, state.w)
    return mixer(T, *tau)                            # 모터 네 개의 추력

행렬로 보기PID 출력 네 개가 모터 네 개가 되기까지

안쪽 루프가 내놓는 건 추력 T 하나와 토크 세 개(롤 τx, 피치 τy, 요 τz)입니다. 모터는 네 개고요. 이 둘을 잇는 게 믹서 행렬이에요. 각 명령을 ‘모터 하나가 맡을 몫’으로 나눠 두면 행렬에는 +1과 −1만 남습니다.

행렬은 열로 읽으면 “이 명령 하나가 모터 네 개를 각각 어느 쪽으로 움직이나”, 행으로 읽으면 “모터 하나의 추력은 네 몫의 합”입니다. 단계를 넘기면 해당 칸이 강조되고, 오른쪽 위에서 본 기체에 같은 색으로 나타나요.

와인드업, 미분 킥, 잡음

적분 와인드업. 모터 힘에는 한계가 있습니다. 목표가 멀어서 모터가 최대로 밀고 있는 동안에도 오차는 계속 쌓이고, I항은 낼 수도 없는 힘을 계속 요구하며 커져요. 목표에 도착할 때쯤엔 I에 엄청난 값이 쌓여 있어서, 그걸 덜어 내느라 크게 지나칩니다. 해결은 간단해요. 출력이 포화된 동안에는 적분을 멈춥니다(조건부 적분, anti-windup).

미분 킥. 목표를 한 번에 바꾸면 오차가 순간적으로 뛰고, 그 순간 오차의 기울기는 무한대에 가깝습니다. D항이 그걸 그대로 곱하면 모터에 순간적으로 거대한 명령이 들어가요. 목표는 바뀌어도 카트의 위치는 순간적으로 바뀌지 않으니, 오차 대신 측정값을 미분하면(−dx/dt) 킥이 사라집니다. 3부의 드론 코드가 −Kd·v를 쓴 이유예요.

센서 잡음. 측정값의 작은 떨림도 미분하면 커집니다. 1 mm 떨림이 0.01초마다 바뀌면 기울기로는 0.1 m/s예요. 그래서 D항에는 거의 항상 저역 통과 필터를 겁니다. 필터는 떨림을 줄이는 대신 반응을 늦춰서, 너무 세게 걸면 D가 브레이크를 늦게 밟게 돼요.

class RealPID:
    def __init__(self, kp, ki, kd, u_lim, tau_f=0.02):
        self.kp, self.ki, self.kd = kp, ki, kd
        self.u_lim, self.tau_f = u_lim, tau_f
        self.integral, self.y_prev, self.d_f = 0.0, None, 0.0

    def update(self, ref, y, dt):
        e = ref - y
        dy = 0.0 if self.y_prev is None else (y - self.y_prev) / dt
        self.y_prev = y
        d_raw = -self.kd * dy                       # 측정값을 미분: 킥 없음
        self.d_f += (d_raw - self.d_f) * dt / (self.tau_f + dt)  # 필터
        i_new = self.integral + e * dt
        u = self.kp * e + self.ki * i_new + self.d_f
        u_sat = np.clip(u, -self.u_lim, self.u_lim)
        if u_sat == u or np.sign(e) != np.sign(u):  # 와인드업 방지
            self.integral = i_new
        return u_sat
